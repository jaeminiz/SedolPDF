# S5.MultiWindowDrag — 스파이크(버릴 코드)

0.8.0 여러 창 계획의 단계 0. 탭을 **포인터 포획 + 화면 좌표 판정**으로 창 밖·다른 창에 끌어 놓을 수 있는지 확인한다.
제품 코드에 복사하지 말 것. 솔루션에 넣지 않았고, 0.8.0이 끝나면 폴더째 지운다.

## 실행

```
dotnet build spikes/S5.MultiWindowDrag -c Release -o .superpowers/out/s5-spike
.superpowers/out/s5-spike/S5.MultiWindowDrag.exe .superpowers/out/s5-spike          # 손으로 끌어 보기
.superpowers/out/s5-spike/S5.MultiWindowDrag.exe .superpowers/out/s5-spike --auto   # 실제 마우스를 움직여 자동 시험(몇 초)
```

로그: `<폴더>/log.txt`

## 결과 (2026-11-06, Windows 11, 모니터 1개 100%, Avalonia 12.1.4)

자동 시험(`--auto`, 실제 마우스 입력) 3회 연속 모두 통과. 각 회 로그 `log-run1..3.txt`.

| # | 확인 | 결과 |
|---|---|---|
| a | 창 밖으로 끌어도 이동 이벤트가 계속 옴 | **통과.** 한 회 이동 이벤트 약 76개 중 62개가 어느 탭 줄에도 없는(창 밖·바탕화면) 위치였고 끊기지 않음 |
| b | 창 밖에서 손을 떼도 놓기 이벤트가 옴 | **통과.** 놓기 이벤트가 끌기 시작한 창에 오고 새 창이 뜸 |
| c | 다른 창 탭 줄 위 판정 | **통과.** W2의 탭을 W1 탭 줄에 놓으면 W1로 옮겨짐(놓기 이벤트는 W2에 옴, 판정은 화면 좌표로) |
| d | Esc 취소 | **통과.** 끌기 중 Esc → 창 수 그대로, 탭 그대로 |
| e | 다른 창이 위에 겹친 경우 | 자동 시험 안 함. 판정은 "최근 활성 창 먼저" 순서로 구현(단계 4 `DropTargetFinder`가 같은 규칙). 손 시험 항목으로 남김 |
| f | 배율 다른 모니터(100%/150%) | **확인 못 함**(모니터 1개). 좌표는 물리 픽셀(`PointToScreen`)로 다루고 탭 줄 안 위치만 그 창 배율로 나눔. 사용자 장비 손 시험 항목 |

발견:
- **같은 컨트롤을 다른 창으로 바로 옮기면 앱이 죽는다** (`ArgumentException: Attempt to call InvalidateArrange on wrong LayoutManager`). 제품은 창마다 탭 모델과 화면 컨테이너를 새로 만들므로(스펙 4.2) 해당 없음. 단계 4에서 끌기 표시(배지)도 창마다 따로 만든다.
- 자동 시험의 첫 실행 1회는 누름 이벤트가 하나도 안 와서 실패했다(창이 막 뜬 직후 입력). 대기 시간을 바꾼 뒤로는 재현 안 됨. 실제 사용과는 무관한 시험 장치 문제로 본다.

**결론: 포획 방식 채택.** 스펙 4.3 그대로 진행한다(DnD로 바꾸지 않음).
