# 글꼴·글자 서식 개선 로드맵 (초안, 2026-11-13)

사용자 보고(0.11.0): Acrobat으로 만든 파란색 글상자(`D:\Downloads\8354-8354499-0.PDF` 2쪽)를 이동하면 글자가 빨간색으로 바뀌고 커진다. 원인 조사 결과 "글꼴 문제"라기보다 **글자 서식을 읽는 방식의 빈틈**이었고, 그 뒤에 시스템 글꼴을 쓰지 못하는 구조적 한계가 있다. 이 문서는 둘을 나눠 순서를 정한다. 구현은 아직 시작하지 않았다.

## 1. 보고된 증상의 원인

PDF 안의 값과 읽는 코드는 직접 확인했다. "움직이면 모양을 다시 그린다"는 부분은 코드(`AnnotationPainter`가 모델에서 그림)와 증상에서 추론한 것이고, 앱에서 직접 재현해 보지는 않았다.

이 주석의 사전(dictionary) 내용:

| 항목 | 값 | 앱이 읽는가 |
|---|---|---|
| `/IT` | `FreeTextTypewriter` | 읽음(타자기) |
| `/DA` | `1 0 0 rg` (빨강, 글꼴·크기 없음) | 읽음 → 글자색 빨강, 크기 없음 |
| `/DS` | **없음** | — |
| `/RC` (리치 텍스트) | 글꼴 맑은 고딕, **10pt, 굵게(700), 색 #0000FF** | **읽지 않음** |
| `/AP` | Acrobat이 그린 모양 | 움직이면 버려지고 앱이 다시 그림 |

- 앱이 `/RC`를 읽는 조건이 `/DS`가 있을 때뿐이다([AnnotationReader.cs](../../src/PdfEditor.Document/Annotations/Reading/AnnotationReader.cs) `ReadFreeText`, `if (hasDs)` 안). Acrobat의 타자기 도구는 `/DS` 없이 `/DA`+`/RC`만 쓰는 일이 흔하다.
- 그래서 색은 `/DA`의 빨강, 크기는 `/DA`에 `Tf`가 없어 기본 12pt가 된다. 실제는 파랑·10pt·굵게다. 굵게는 `/DS`/`/RC`에서 아예 읽지 않는다(`DefaultStyle`은 "굵게·기울임은 읽지 않는다").
- 움직이는 순간 주석이 "수정됨"이 되어 `AnnotationPainter`가 모델에서 모양을 다시 그리므로, 그때 위 값들이 눈에 보인다. 처음 열 때 파랗게 보이는 건 Acrobat이 만든 `/AP`가 그대로 그려지기 때문이다.
- 글꼴 대체(맑은 고딕 → 앱 내장 Noto Sans KR)는 이 증상의 원인이 **아니다.** 다만 글자 폭이 달라져 줄바꿈이 바뀔 수 있어 "더 커 보이는" 느낌을 키운다.

## 2. 지금 글꼴 구조와 한계

- 번들 글꼴은 Noto Sans KR(고딕)·Noto Serif KR(명조) Regular 두 개뿐이다(OFL 1.1, `assets/fonts/`). 용량은 약 12 MB.
- 글꼴 선택은 **고딕/명조 이분법**이다(`AppFontCatalog.Classify`, `TextFontFamily { Sans, Serif }`). 원래 글꼴 이름("맑은 고딕", "Arial" 등)은 저장하지 않는다.
- 굵게·기울임은 **가짜**다(굵게는 렌더 모드 2의 테두리, 기울임은 기울임 행렬). 실제 굵은 글꼴 파일은 없다.
- 시스템 글꼴을 직접 고르는 기능은 "범위 밖"으로 명시돼 있다(`AppFontCatalog` 주석).
- `/RC`의 글자 단위(span) 서식은 모델에 없다. 한 주석은 글꼴·크기·색·굵기가 하나씩이다.

이 때문에 생기는 문제: 원본 주석의 글꼴 이름·크기·색·굵기가 편집·이동 후에 사라지거나 바뀌고, 사용자가 자기 PC의 글꼴을 쓸 수 없다.

## 3. 단계별 계획

### 0.11.2 — 긴급 수정 (작고 안전하게)
1. `/RC`를 `/DS` 유무와 상관없이 읽는다. 첫 span·`body`의 `color`, `font-size`, `font-weight`, `font-family`를 `/DS` → `/RC` → `/DA` 순으로 덮어쓴다(Acrobat 관례: 사용자가 바꾼 값은 `/RC`에 있고 `/DS`는 처음 값).
2. 굵게(`font-weight` ≥ 600)와 기울임(`font-style: italic`)을 읽어 서식 모델에 넣는다.
3. 이동·크기 조절만 한 주석은 모양을 다시 그리지 않고 기존 `/AP`를 새 `/Rect`에 맞춰 옮긴다(내용·서식을 바꾼 경우에만 다시 그림). 원본을 가장 덜 건드리는 방법이라 같은 종류의 문제를 다른 PDF에서도 막는다.
4. 회귀 시험: 이 파일의 해당 주석만 줄인 시험용 PDF를 `tests/fixtures`에 넣고 "읽은 색·크기·굵기 = 파랑·10pt·굵게", "이동 후에도 같음"을 확인한다.
- 범위가 작아 0.11.2로 낼 만하다. 출시 정책상 스토어·GitHub 푸시는 보안·치명적 버그만이므로, 사용자가 이 문제를 치명적으로 보는지에 따라 0.12.0에 묶을 수도 있다.

### 0.12.0 — 서식 보존 (왕복에서 잃지 않기)
1. 주석 모델에 **원래 글꼴 이름**(예: 맑은 고딕)을 따로 저장하고, `/DA`·`/DS`·`/RC`를 다시 쓸 때 원래 이름을 그대로 돌려 쓴다. 화면에는 내장 글꼴로 그려도 파일에는 원래 이름이 남는다.
2. `/RC`의 span 단위 서식(한 주석 안에서 글자마다 색·굵기가 다른 경우)을 읽어 **보존**한다(편집 UI는 아직 한 주석 한 서식이어도, 건드리지 않은 부분은 그대로 유지).
3. 굵게·기울임 UI를 실제 속성 값(font-weight, italic)과 맞춘다.

### 0.13.0 — 시스템 글꼴 사용
1. 설치된 글꼴 목록을 읽는다(Avalonia/DirectWrite). 목록에서 글꼴을 고르는 UI를 속성 패널·서식 탭에 추가한다.
2. 고른 글꼴을 PDF에 **서브셋으로 포함**한다. 포함 허용 여부는 글꼴 파일의 `OS/2 fsType`으로 확인한다(`AppFontCatalog.FsTypeAllowsEmbedding`이 이미 있다). 포함이 금지된 글꼴은 고르지 못하게 하거나 대체 글꼴과 안내를 보여 준다.
3. 글꼴 모음(.ttc)·가변 글꼴·시스템에 없는 글꼴(받은 사람의 PC에 없을 때)을 어떻게 할지 정한다. 기본은 "포함 가능한 글꼴은 항상 포함".
4. 라이선스 원칙은 유지한다: **번들에 넣는 글꼴은 OFL 등 재배포 가능한 것만.** 시스템 글꼴은 번들이 아니라 사용자 PC 것이므로 번들 규칙과 별개지만, PDF에 포함할 때는 위 fsType 검사를 거친다.

### 0.14.0 — 모양 일치도
1. 맑은 고딕·Arial·바탕 등 흔한 글꼴 → 내장 글꼴 **대체표**와 폭 보정으로 줄바꿈을 원본에 가깝게 맞춘다(`TextMeasure`).
2. 실제 Bold(그리고 Italic) 글꼴 파일 번들 여부를 결정한다. 가짜 굵게보다 보기 좋지만 Noto Sans KR Bold만 해도 약 +4.6 MB다.
3. 미리보기(편집 중 화면)와 저장 결과(PDF)의 글꼴·줄바꿈이 같은지 검증하는 시험을 만든다.
