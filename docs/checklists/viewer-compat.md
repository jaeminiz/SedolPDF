# 뷰어 호환성 점검표

같은 샘플 PDF를 여러 뷰어에서 열어 모양이 같은지 확인합니다. (설계서 8.3, 수동 점검)

## S1 샘플: 한글 텍스트 상자 (FreeText)
- 파일: `spikes/out/s1-freetext.pdf` (테스트를 돌리면 다시 만들어집니다)
- 기대 모양: 페이지 왼쪽 위(가로 1인치, 세로 1인치 부근)에 `가나다 도면 검토 ABC` 한 줄이 검은 글씨로 보임
- 점검 일시: 2026-10-15
- 점검자: 사용자 (스크린샷 확인: PDF-XChange, Acrobat Pro, Chrome 계열 브라우저)

| 뷰어 (버전) | ① 글자 표시 | ② 모양 동일 | ③ 선택 후 이동해도 유지 | ④ 텍스트 복사 | 메모 |
|---|---|---|---|---|---|
| Adobe Acrobat Pro | ○ | ○ | 미확인 | 미확인 | Reader가 아닌 Pro로 확인 |
| PDF-XChange Editor | ○ | ○ | 미확인 | 미확인 | |
| Foxit | 미확인 | 미확인 | 미확인 | 미확인 | 설치되지 않았거나 미점검 |
| Chrome 기반 브라우저 | ○ | ○ | 해당 없음 | 미확인 | 보기 전용 |

### 각 칸에 적는 방법 (○ 정상 / △ 조금 이상 / × 안 됨, 이상하면 메모에 현상을 적기)
- ① 글자 표시: 한글과 영문이 모두 깨지지 않고 보이는가 (네모 □, 물음표, 빈칸이면 ×)
- ② 모양 동일: 글자 크기·위치가 다른 뷰어와 비슷한가
- ③ 선택 후 이동해도 유지: 주석 도구로 상자를 클릭해 조금 옮겨 보고, 글자가 그대로인가 (뷰어가 모양을 다시 만들어도 한글이 유지되는가)
- ④ 텍스트 복사: 상자의 글자를 복사해 메모장에 붙여 넣으면 `가나다 도면 검토 ABC`가 나오는가 (뷰어가 복사를 지원하지 않으면 "해당 없음")

## S3 샘플: 폰트 대체 결과 (PDFium 방식)
- 파일: `spikes/out/s3-fallback.pdf` (PDFium의 `FPDFText_LoadFont`로 Noto Sans KR을 넣은 텍스트 `ABC가`)
- 점검 일시: 2026-10-15 (사용자 스크린샷)

| 뷰어 | 글자 표시 | 메모 |
|---|---|---|
| Adobe Acrobat Pro | × | `ABC` 뒤의 `가`가 네모(□)로 표시됨 |
| PDF-XChange Editor | × | 같은 현상 (`ABC□`) |
| Chrome 기반 브라우저 | ○ | `ABC가` 정상 |

결론: PDFium `FPDFText_LoadFont`에 CFF 기반 OpenType(Noto Sans KR)을 넣는 방식은 PDFium·Chrome에서만 보이고 Acrobat·PDF-XChange에서는 깨진다. M4 폰트 대체는 S1 방식(서브셋 + 순수 CFF + CIDFontType0C)으로 해야 한다.

## M1 페이지 편집 샘플 (Task 13)
- 만드는 방법: 앱에서 여러 쪽짜리 PDF(예: `spikes/out/bench-a4-300pages.pdf`를 복사한 것)를 열고 아래 편집을 한 뒤 "다른 이름으로 저장"합니다. 원본은 건드리지 마세요.
  1. 3쪽 삭제 → 5쪽을 오른쪽으로 회전 → 7쪽을 "위치 지정"으로 맨 앞으로 이동 → 1쪽 뒤에 빈 페이지 삽입 → 다른 PDF에서 2~3쪽 삽입
  2. 별도로 "병합"으로 PDF 2개를 합친 문서도 저장
- 자동으로 확인한 것: 저장한 파일을 PDFium으로 다시 열어 쪽 순서와 쪽 크기(회전 반영)가 편집 결과와 같음 (`EditedDocument_SavedAndReopened_KeepsOrderAndRotation`). Chrome·Acrobat·PDF-XChange에서 여는 것은 자동화하지 않았음 → **검증 필요(사용자 점검)**

- 점검자: (미점검)

|---|---|---|---|---|---|
| Adobe Acrobat Pro | 미확인 | 미확인 | 미확인 | 미확인 | |

| Chrome 기반 브라우저 | 미확인 | 미확인 | 미확인 | 미확인 | |

- ① 쪽 수·순서: 앱 썸네일 순서와 뷰어의 쪽 번호 순서가 같은가 (○ 정상 / △ 조금 이상 / × 안 됨)
- ② 회전: 앱에서 오른쪽으로 돌린 쪽이 뷰어에서도 같은 방향으로 돌아가 있는가 (왼쪽·오른쪽이 뒤바뀌면 ×)
- ③ 빈 쪽: 앞 쪽과 같은 크기의 흰 쪽이 들어갔는가
- ④ 병합: 병합 대화상자에서 정한 파일 순서대로 쪽이 이어지는가

### M1 점검 요약 (Task 18 정리, 2026-10-16)
| 항목 | 자동 확인 | 사용자 점검 |

## M2 주석 샘플 (Task 17)
- 파일: `spikes/out/m2-annotations.pdf` (3쪽, `M2CompatSampleTests`를 돌리면 다시 만들어집니다. 쪽별 미리보기 `m2-annotations-p1~3.png`도 함께 생깁니다.)
- 기대 모양 (PDFium으로 렌더해 눈으로 확인한 모양):
  - **1쪽:** 위쪽에 빨간 물결 연필 선, 그 오른쪽에 노란 스티커 메모 아이콘. 아래로 반투명 노란 형광펜 띠, 파란 밑줄, 빨간 취소선(밑줄·취소선은 가는 선). 그 아래 노란 채우기+빨간 테두리 사각형(왼쪽)과 파란 타원(오른쪽). 맨 아래 반투명 초록 "영역 강조" 사각형(메모 내용: `영역 강조: 이 부분 치수 재확인`). 모든 주석의 메모 내용은 한글입니다.
  - **2쪽:** 옆으로 누운 쪽(`/Rotate 90`). 스티커 메모 아이콘이 **똑바로** 보이고(옆으로 누우면 ×), 파란 연필 곡선이 있음.
  - **3쪽:** Acrobat식 원본(`CreateMixed`)에서 ① 빨간 사각형이 오른쪽 아래로 옮겨져 있고(원래 자리에는 없음), ② 스티커 메모의 내용이 `내용을 바꾼 메모 (M2)`, ③ 검은 X자 연필 선 중 가운데 부분이 지워져 끊겨 있음. 나머지(노란 형광펜 2줄, 초록 채움 원, 밑줄·취소선, 회색·빨간 사각형 등)는 원래 그대로.

- ② 반투명 형광펜: 노란 띠 뒤가 비쳐 보이는가(다른 뷰어가 불투명하게 칠하면 ×)

- ⑤ 3쪽에서 사각형이 옮겨진 자리에, 메모 내용이 바뀐 글로, 연필이 끊긴 채 보이는가(뷰어가 예전 모양을 그대로 쓰면 ×)
- ⑥ 각 뷰어의 인쇄 미리보기(또는 PDF로 인쇄)에 위 주석이 모두 나오는가
- 앱에서 자동으로 확인한 것: 저장한 파일을 다시 읽어 1쪽 8개·2쪽 2개가 읽히고, 3쪽의 이동·내용·획 수가 편집 결과와 같으며 2쪽 회전이 유지됨 (`M2CompatSampleTests`). 다른 뷰어에서의 모양은 **검증 필요(사용자 점검)**.
