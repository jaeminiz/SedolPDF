# 문서 탭 자동 축소·탭 끌기·썸네일 끌어 쪽 옮기기 결과 (2026-10-21)

v0.2.0 사용 중 사용자 보고(긴 파일명 탭 6개에서 탭 줄이 넘쳐 `+` 버튼이 가려짐) 3건.

## 바뀐 것
1. **탭 폭 자동 축소** — `Shell/TabStripPanel`(새 배치판). 탭 폭 = (사용 가능한 폭 − 간격) ÷ 탭 수를 72~240 px로 제한. 제목은 `…`로 줄이고 전체 제목은 툴팁. 닫기(×)는 탭 안 오른쪽 칸에 고정, `+`는 줄 밖 칸이라 항상 보임. 72 px에서도 넘치면 고른 탭이 보이게 줄을 왼쪽으로 밀어 넘친 부분을 잘라 냄(가로 스크롤 막대·넘침 메뉴는 만들지 않음 — 가장 단순한 처리).
2. **탭 끌어 순서 바꾸기** — `MainWindow.axaml.cs`의 포인터 처리(6 px 넘게 끌면 시작, 닫기 단추는 제외) + `MainWindowViewModel.MoveDocument` + `TabReorder`(놓일 자리·새 번호 계산). 끄는 동안 파란 삽입 선, Esc 취소, 손을 뗄 때 한 번만 `Documents.Move`(문서·편집 내용 그대로, 고른 탭 유지).
3. **썸네일 끌어 쪽 옮기기** — `ThumbnailsPanel`의 포인터 처리 + `PageCommandsViewModel.MovePagesToDropAsync`(기존 `MovePagesCommand` 재사용, 새 PDF 쓰기 코드 없음). 끌어 온 쪽이 고른 쪽에 들어 있으면 고른 쪽 전부, 아니면 그 쪽 하나. 삽입 선 표시·가장자리 자동 스크롤·Esc 취소. 순서가 안 바뀌는 자리면 아무 것도 안 함. 실행 취소 한 번에 복원. 여러 쪽을 고른 채 그중 하나를 눌러 끌 수 있도록, 수정키 없이 고른 쪽을 누르면 선택 정리는 손을 뗄 때(끌지 않았을 때)로 미룸.
   - 파일 끌어 넣기와 충돌 없음: 파일 끌어 놓기는 기존 `DragDrop` 이벤트, 쪽 옮기기는 포인터 이벤트라 서로 다른 경로.

## 확인한 것
- 시험 추가: `DocumentTabsTests`(탭 폭·밀기·놓일 자리·새 번호·`MoveDocument` 고른 탭 유지) + `PageCommandsViewModelTests`(끌어 옮기기 선택/비선택/같은 자리/맨 끝/실행 취소 한 번, `TryMoveDestination`). `dotnet test PdfEditor.sln` 전부 통과, 경고 0.
- 내가 띄운 창(Release 빌드, 임시 폴더)을 `PrintWindow`로 캡처: 긴 이름 탭 6개가 한 줄에 균등 축소 + `…` + `×`·`+` 모두 보임 (사용자 화면 캡처 없음).
- `--bench`(변경 후): A1 첫 화면 0.458·0.376·0.373 s(목표 ≤0.5 통과), 300쪽 작업 집합 389.8 MB(목표 <400 통과, 여유 작음 — M4x 때 383~389 MB와 같은 범위).

## 검증 필요 (실제 마우스로 확인 못 함)
- `PostMessage`로 보낸 마우스 메시지는 Avalonia 포인터로 전달되지 않아 **탭 끌기·썸네일 끌기의 실제 동작(삽입 선 위치, Esc 취소, 자동 스크롤, 여러 쪽 함께 끌기)은 사용자 PC에서 직접 확인 필요**. 계산 부분(놓일 자리, 새 번호, 명령 연결)은 시험으로 확인.
- 125/150% 배율, 탭 20개 이상(최소 폭 넘침)에서의 모양.
- 끌 때 포인터를 캡처하므로, 다른 창 위로 나갔다 돌아오는 경우의 동작.
