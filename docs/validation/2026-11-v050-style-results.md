# 0.5.0 글자 서식 결과 (선 종류·화살촉 확장은 철회)

작성: 2026-11-03 · 브랜치 `claude/v050-style-4a3ecd`

## 철회한 것 (사용자 점검 결과)
PDF-XChange·Acrobat에서 열어 보고 선을 고치자 원본이 변형됐다: 이중선은 굵은 한 줄로, 설명선 지시선은 검은 굵은 선으로, 채운/속 빈 화살촉은 뷰어 규칙대로 바뀜. 원인은 PDF 표준에 없는 표현(`/SedolLS /Double`, `/SedolLE`, 긴 점선, 설명선 지시선 모양)이라 뷰어가 AP를 다시 만들 때 사라지는 것. 선 종류도 과하다는 판단에 따라 **0.4.0 범위(실선·점선·파선·일점쇄선, 표준 `/LE` 화살촉)만 남기고 이번에 더한 선 관련 기능을 모두 되돌렸다**(커밋 3be4465 revert).

## 만든 것: 글자 서식 (텍스트 상자·타자기·설명선, 상자 전체 단위)
- 글꼴 2종(앱 내장 Noto Sans KR 고딕 / Noto Serif KR 명조), 굵게, 기울임, 밑줄, 취소선.
- 합성 굵게(렌더 모드 2 + 글자 크기×0.03 선)·기울임(전단 0.21)·밑줄·취소선(굵기 ×0.06, 기준선 −0.12·+0.30 em). 화면과 AP가 같은 Painter 코드를 쓴다. 명조 파일이 없으면 고딕으로 물러남.
- 저장: 비표준 `/SedolFont`·`/SedolFmt`(기본이면 키 없음). AP 글꼴은 가족별 서브셋 임베드(패처 수정).
- UI: 속성 패널·형식 탭 글꼴 목록 + B/I/U/S, 글 편집 칸 미리보기, 이름 붙인 스타일, XFDF 유지.

## 검증
- 시험: `V050TextFormatTests`, `V050StyleXfdfTests`, `V050StylePropertiesTests`, `ScreenMatchesPdfTextFormatTests`(화면↔PDFium 7조합), `V050CompatSampleTests`(샘플 생성).
- 전체 `dotnet test`(철회 후): 실패 0 (App 716, TextEdit 259, Document 276, Appearance 250, Exchange 73, ContentStream 72, Pdf.Native 97, Pages 48).

## 한계·검증 필요
- 글자 서식도 비표준 키라, 다른 편집기에서 글을 고치면 서식이 사라질 수 있다(선 서식과 같은 종류의 위험). 다른 뷰어에서의 모양은 미확인(점검표: `docs/checklists/viewer-compat.md` 0.5.0 절).
- 굵게는 합성이라 진짜 Bold보다 획이 균일하지 않고, 기울임은 전단 변형.
- 입력 중 편집 칸은 시스템 글꼴에 속성을 준 근사. 직접 화면 확인 안 함(헤드리스만).
- 참고(0.4.0부터 있던 동작, 이번에 안 바꿈): 닫힌 화살촉은 `/IC`가 없으면 앱은 선 색으로 채우지만 다른 뷰어는 속 빈 모양으로 다시 그린다.
