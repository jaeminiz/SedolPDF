# 0.5.0 주석 서식 묶음 결과 (선 종류·화살촉·글자 서식)

작성: 2026-11-03 · 브랜치 `claude/v050-style-4a3ecd` · 대상: 선·폴리라인·다각형·설명선 지시선의 선 모양/화살촉, 텍스트 상자·타자기·설명선의 글자 서식.

## 만든 것
### A. 선 종류·화살촉
- 선 모양 6종: 실선·점선·파선·**긴 점선(신규)**·일점쇄선·**이중선(신규)**. 점·파선·일점쇄선은 0.4.0에 있었고 이번에 긴 점선·이중선을 더함. 모두 굵기에 비례.
- 화살촉 8종: 열린·**닫힌(속 빈, 신규)**·채운·마름모·원·사각·빗금·막대. 기존 `ClosedArrow`는 선 색(또는 `/IC`)으로 채우는 "채운 화살표"로 이름만 바꿔 표시(동작 불변), 속 빈 쪽을 `HollowArrow`로 추가. 화면 문구: 채운 화살표 / 닫힌 화살표.
- 적용 대상: 선·폴리라인·다각형(선 모양+화살촉은 선·폴리라인), **설명선 지시선**(선 모양과 끝 모양; 상자 테두리는 항상 실선).
- 저장 형식:
  | 값 | PDF 키 |
  |---|---|
  | 점선·파선·긴 점선·일점쇄선 | 표준 `/BS << /S /D /D [..] >>` |
  | 이중선 | 표준 `/BS`는 실선, **비표준 `/SedolLS /Double`**, AP가 굵기/3 두 줄 |
  | 화살촉 8종 | 표준 `/LE` 이름(ISO 32000 표 176) |
  | 속 빈 닫힌 화살촉 | `/LE /ClosedArrow` + **비표준 `/SedolLE [..]`** 표시 |
  | 설명선 지시선 선 모양 | 비표준 `/SedolLS` |
- 화면과 AP가 같은 Painter 코드(`AnnotationPainter.AddStyled`, `DoubleStroke`, `LineEndings`)를 쓴다. 이중선은 경로를 ±굵기/3 옮긴 두 선(마디는 뾰족한 이음새, 거의 되접히면 한쪽 법선), 채움이 있는 다각형은 채움 Op + 두 닫힌 선. 구름 테두리·길이 0 선은 실선으로 처리.
- 형식 탭·속성 패널의 선택 UI(선 모양 목록, 화살촉 목록)에 추가. 이름 붙인 스타일(저장·적용)과 XFDF 내보내기/가져오기 유지(이중선·속 빈 촉·지시선 모양은 비표준 속성 `sedolls`, `sedolhead`, `sedoltail`).

### B. 글자 서식 (텍스트 상자·타자기·설명선, 상자 전체 단위)
- 글꼴 2종(앱 내장 Noto Sans KR 고딕 / Noto Serif KR 명조, 사용자 결정 U1), 굵게, 기울임, 밑줄, 취소선.
- **합성** 굵게·기울임(내장 글꼴에 변형 없음): 굵게 = 채움+선(렌더 모드 2, 선 굵기 = 글자 크기 × 0.03, 선 색 = 글자 색), 기울임 = 글리프 원점 기준 전단 0.21, 밑줄·취소선 = 줄마다 글자 색 가는 선(굵기 글자 크기 × 0.06, 기준선 −0.12·+0.30 em). 화면(글리프 윤곽선 + 펜)과 AP(내용 스트림)가 같은 `TextRunOp`/Op를 쓴다. 굵게·기울임 비율은 M5의 `AppFontCatalog` 상수를 재사용.
- 명조 파일이 없으면 화면·AP 모두 고딕으로 물러남(`PaintContext.FontFor`).
- 저장: 비표준 `/SedolFont /Serif`(고딕이면 키 없음), `/SedolFmt`(굵게 1·기울임 2·밑줄 4·취소선 8). 기본 서식이면 키를 쓰지 않아 이전 파일과 출력이 같다. `/DA` 글꼴은 `/Helv` 그대로, 서식 있는 글(`/RC`)은 만들지 않음(범위 밖). AP 글꼴은 가족별 서브셋(`NotoSerifKR` 등)을 임베드하도록 패처의 `AddApFont`가 가족을 따라가게 고침(이전에는 항상 고딕).
- UI: 속성 패널·형식 탭에 글꼴 목록 + B/I/U/S 토글. 글 편집 칸(입력 중)에도 굵게·기울임·밑줄·취소선·명조 미리보기 적용. 이름 붙인 스타일에 글꼴·서식 포함, XFDF 유지.
- 타자기는 서식·글꼴 변경 때 상자를 다시 맞추고, 기울임이면 오른쪽으로 밀리는 만큼(≈0.21×글자 크기×0.8) 상자를 넓힌다.

## 검증 결과
- 새 시험(통과): `V050LineStyleTests`(Painter 출력·이중선 렌더·지시선), `V050LineStyleRoundTripTests`(저장→읽기·파일 키), `V050TextFormatTests`(내용 스트림·왕복·명조 임베드·알 수 없는 키 보존), `V050StyleXfdfTests`(XFDF), `V050StylePropertiesTests`(패널·스타일 모델), `ScreenMatchesPdfTextFormatTests`(화면 Avalonia 렌더 ↔ PDFium 렌더, 7개 서식 조합), `V050CompatSampleTests`(샘플 생성).
- 기존 시험 2건을 새 열거값에 맞게 고침(`LineEnding` 이름 왕복에서 HollowArrow 제외, 화살촉 선택 수 8→9, 선 모양 수 4→6).
- 전체 `dotnet test`: 솔루션 전체 4회 실행 중 3회는 실패 0·경고 0, 1회(3번째)는 `PdfEditor.ContentStream.Tests` 1건 실패(72개 중 71개 통과). 이 프로젝트는 이번 변경이 건드리지 않았고, 단독 3회 재실행과 직후 전체 재실행에서 72/72 통과해 간헐 실패(시험 병렬 실행 부하 추정, 원인 시험 이름은 로그를 남기지 않아 미확인)로 본다. 마지막 전체 실행 기준 개수: Appearance 271, Document 291, Exchange 84, App 719, TextEdit 259, ContentStream 72, Pdf.Native 97, Pages 48 (+ 스파이크 시험). 따라서 "연속 3회 통과"는 엄밀히는 (통과, 통과, 간헐 실패, 통과)이다 — 사용자 판단 필요.
- 호환성 샘플(저장소 무시 폴더라 커밋되지 않음, `V050CompatSampleTests`로 다시 만들어짐): `spikes/out/v050-style-lines.pdf`, `spikes/out/v050-style-text.pdf` + 쪽별 PNG. 점검표는 `docs/checklists/viewer-compat.md` 0.5.0 절.

## 한계·검증 필요 (사용자 점검)
- **다른 뷰어 미확인**: Acrobat·PDF-XChange·Foxit·Chrome에서 이중선(두 줄), 속 빈/채운 화살촉 구분, 굵게 번짐 정도, 기울임, 명조 글자가 어떻게 보이는지 확인하지 못했다. AP를 다시 만드는 편집기에서 글을 고치면 `/Sedol*` 키를 모르므로 이중선·속 빈 촉·서식이 사라질 수 있다(알려진 한계).
- 다른 프로그램이 만든 PDF에서 읽은 글꼴·굵기는 서식 값으로 읽지 않는다(`/SedolFont`·`/SedolFmt`만). 기존 PDF 글(M5 문단) 서식 변경과 서식 있는 글(`/RC`)·시스템 글꼴 전체 선택은 범위 밖.
- 굵게는 합성이라 진짜 Bold 글꼴보다 획이 균일하지 않을 수 있고, 기울임은 전단 변형이라 진짜 이탤릭이 아니다.
- 글 입력 중(편집 칸)의 모양은 시스템 글꼴(명조는 Noto Serif KR/바탕 계열 후보 목록)에 굵게·기울임 속성을 준 근사다. 확정하면 Painter 결과(저장 모양)로 돌아온다. 입력 칸은 밑줄·취소선 장식만 준다.
- 설명선 상자 테두리와 일반 텍스트 상자 테두리의 선 모양, 사각형·타원·연필의 선 모양은 이번 범위 밖(실선만).
- 직접 화면 조작 시험은 하지 않았다(헤드리스 시험만). 형식 탭의 레이아웃(글꼴 목록·토글 줄 추가 후 리본 폭)은 실제 화면 확인이 필요하다.
- `AnnotationStyle` 설정 JSON에 `TextFont`·`TextFormat` 필드가 추가됨(옛 설정은 null = 건드리지 않음).
