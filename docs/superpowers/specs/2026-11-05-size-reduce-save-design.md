# 용량 줄여 저장 + 외부 주석 선택 버그 (0.7.0) 설계

- 작성일: 2026-11-05
- 요청: 사용자. 메일 첨부 한도(20MB, 안전선 16MB) 때문에 목표 용량에 맞춰 줄여 저장하는 기능(Acrobat의 "크기가 축소된 PDF"/"최적화된 PDF" 대응)을 넣는다. 같은 버전에 Xgard 데이터시트 4쪽 주석 선택 버그를 고친다.
- 경로: 아키텍처(새 하위 기능). 설계 승인: 2026-11-05 사용자("오케이").

## 목표와 비목표

**목표**
- 목표 용량(MB)을 입력하면 그 이하의 새 PDF를 만든다. 원본은 건드리지 않는다.
- 텍스트·벡터·주석은 그대로 둔다(선택·검색·편집 유지). 줄이는 대상은 이미지다.
- 목표를 못 맞추면 사용자가 그 자리에서 고른다: 그 상태로 저장 / 이미지로 변환해 목표에 맞춤(텍스트·링크·주석 사라짐 경고) / 취소.
- 의존성은 MIT/BSD/Apache/OFL만. 추가 패키지는 SkiaSharp(MIT, Avalonia가 이미 번들)뿐.

**비목표 (이번 버전 제외)**
- 암호 문서(안내만: "암호가 있는 문서는 아직 지원하지 않습니다").
- 래스터화 결과의 검색 가능 텍스트 복원(OCR).
- 세부 옵션 대화상자("최적화된 PDF" 고급 옵션): 다음 버전 후보.
- JPX·CCITT·JBIG2 이미지 재압축(건드리지 않고 그대로 둔다).

## 사용 흐름

1. 메뉴: 파일 → 다른 형식으로 저장 → "용량 줄여 저장…".
2. 대화상자: 현재 용량 표시, 목표 용량(MB, 기본 16, 프리셋 8·16·20), 저장 위치(기본 `이름_축소.pdf`, 원본과 같은 경로는 거절).
3. 현재 용량이 이미 목표 이하면 "이미 충분합니다"를 알리고 끝낸다(저장 안 함).
4. 진행률 + 취소. 끝나면 "52.3MB → 15.8MB"를 보여 준다.
5. 못 맞추면 선택 대화상자: "최소 N MB까지 줄었습니다(목표 M MB)". 버튼 3개(그 상태로 저장 / 이미지로 변환해 저장 / 취소). 두 번째는 한 번 더 확인("텍스트·링크·주석이 사라집니다").

## 처리 순서 (서비스 `SizeReducer`)

1. **사본**: 편집 중인 문서는 `OutputCopyBuilder.BuildAsync`로 임시 사본을 만든다(편집 세션 불변, 같은 모델이면 결과 동일).
2. **무손실 정리**: PDFsharp으로 열어 안 쓰는 객체 제거, 스트림 재압축(Flate), 중복 리소스 합치기. 이 단계 크기가 "이미지 외 고정분"이다.
3. **이미지 재압축**: 이미지 XObject마다 실제 표시 크기(쪽 위치 행렬)로 유효 dpi를 계산한다. 사다리(아래 표)의 단계 L에서 `유효 dpi > 최대 dpi`면 줄이고, JPEG(DCTDecode)로 다시 인코딩한다. 확대는 하지 않고, 결과가 원본보다 크면 원본을 유지한다. 같은 이미지가 여러 쪽에 쓰이면 한 번만 처리한다. 투명(SMask)·ImageMask는 건드리지 않거나 보존한다. 처리 못 하는 형식은 그대로 둔다.
4. **단계 선택**: 각 단계의 예상 합계(고정분 + 이미지 예상 크기 합)로 목표 이하인 가장 약한 단계를 고른다(안전 여유 3%). 실제로 저장해 크기를 확인하고, 초과하면 한 단계 더 낮춘다. 가장 센 단계도 초과하면 5단계 흐름의 선택 대화상자로 간다.
5. **래스터화(사용자가 고른 경우만)**: 쪽마다 PDFium으로 그려 JPEG으로 압축해 새 PDF로 조립한다(쪽 크기·회전 유지). 래스터 사다리로 목표에 맞춘다.
6. 임시 파일 정리, 결과(전후 용량, 선택한 모드)를 돌려준다.

**이미지 사다리** (최대 dpi / JPEG 품질)

| 단계 | 최대 dpi | 품질 |
|---|---|---|
| 0 | 300 | 85 |
| 1 | 200 | 80 |
| 2 | 150 | 70 |
| 3 | 120 | 60 |
| 4 | 96 | 45 |

**래스터 사다리** (쪽 dpi / 품질): 150/70 → 120/60 → 96/50 → 72/40.

## 구성

- 새 프로젝트 `src/PdfEditor.Optimize` (참조: Pdf.Native, PdfEditor.Document; 패키지: PDFsharp 6.2.4, SkiaSharp). 테스트 `tests/PdfEditor.Optimize.Tests`.
  - `SizeLadder` : 사다리 정의 + 단계 선택 계산(순수 함수).
  - `ImageRecompressor` : 이미지 찾기·유효 dpi·다시 인코딩(PDFsharp + Skia).
  - `Rasterizer` : 쪽 그리기 + JPEG 조립.
  - `SizeReducer` : 진입점 `ReduceAsync(DocumentSession, string targetPath, long targetBytes, IProgress<…>, CancellationToken)` → `ReduceResult { Achieved, FinalBytes, MinPossibleBytes, Mode }`.
- 앱: `ReduceSizeDialog`(+VM), 메뉴/명령 `file.reduceSize`, ko/en 문구(Strings.resx/.en.resx/Strings.cs). 단축키 없음.
- 기존 코드 변경 최소: `MainWindowViewModel` 명령 등록, 메뉴 항목 추가.

## 오류·안전

- 암호 문서: 시작 전에 막는다. 원본 경로와 같은 저장 위치 거절. 디스크 오류·취소 시 임시 파일 삭제, 대상 파일은 완성본일 때만 만든다(임시에 쓰고 이동).
- 줄인 결과 검증: 쪽 수 동일, 파일이 열림, 줄인 쪽을 작게 그려 원본과 비교(이미지 쪽 허용 오차 넓게; 기존 충실도 비교 방식 재사용).
- 벡터 도면처럼 이미지가 거의 없어 못 줄이는 경우는 선택 대화상자에서 "이미지가 거의 없어 더 줄일 수 없습니다"를 보여 준다.

## 시험

- 서비스: 이미지가 섞인 합성 PDF(JPEG, Flate, 투명, CMYK, 여러 쪽에서 공유)로 ① 목표 이하 달성 ② 원본 불변 ③ 이미 작으면 저장 안 함 ④ 못 맞추면 `Achieved=false`와 최소 용량 ⑤ 취소 시 임시 파일 없음 ⑥ 래스터화 결과 쪽 수·크기 일치.
- `SizeLadder`: 예상치가 목표 근처일 때 단계 선택 경계값.
- 앱: 대화상자 기본값·프리셋·검증(원본과 같은 경로), 선택 대화상자 3버튼 흐름.

## 부분 B: 외부 도구가 만든 주석 선택 버그 (Xgard 4쪽)

**증상**: 첨부 `Xgard-Data-Sheet-Interactive (1).pdf` 4쪽의 빨간 사각 테두리(Square)와 "신뢰도" 글자(FreeText)가 선택되지 않는다.

**원인 (실측, `AnnotationReader.Read`로 확인)**: 둘 다 앱이 편집할 수 없는 "읽기 전용"으로 분류해 선택 대상에서 빠진다.
1. FreeText `/IT /FreeTextTypewriter`(Acrobat·PDF-XChange 철자). 읽기 코드는 `/FreeTextTypeWriter`(대문자 W)만 알아 `UnsupportedType`이 된다(`AnnotationReader.cs:404`). 쓰기 코드는 `/FreeTextTypeWriter`로 쓴다.
2. Square의 `/RD [0.5 0.5 0.5 0.5]`(테두리 폭의 절반). 일반 Square/Circle에 0이 아닌 `/RD`가 있으면 `RectDifferences`로 읽기 전용이 된다(`AnnotationReader.cs:224`).

**수정**
- B1: 읽기에서 `/FreeTextTypewriter`와 `/FreeTextTypeWriter`를 모두(대소문자 무시) 타자기로 인정한다. 쓰기는 기존(`/FreeTextTypeWriter`) 유지.
- B2: Square/Circle의 균일하지 않아도 되는 `/RD`를 지원한다. 읽을 때 모양 사각형 = `/Rect`에서 `/RD`만큼 안쪽(PDF 규격). 고쳐서 저장할 때 `/RD`는 0으로 쓰고 `/Rect`를 모양 사각형으로 쓴다(`PatchPlanBuilder`의 기존 `/RD` 0 쓰기와 같은 방식). 건드리지 않은 주석은 원본 그대로 둔다. 클라우드 Square의 기존 예외는 유지.
- 시험: 합성 PDF(`/RD`가 있는 Square, `/FreeTextTypewriter` FreeText)로 ① 읽으면 편집 가능 ② 테두리를 눌러 선택 ③ 옮기고 저장하면 다시 읽어도 같은 위치 ④ 건드리지 않으면 원본 바이트 불변. 첨부 파일 자체는 저장소에 넣지 않고(저작권·용량), 있으면 읽어 확인하는 선택적 시험만 둔다.

## 열어 둔 가정 (구현 첫 단계에서 확인)

- PDFsharp 저장이 도달 불가 객체를 버리는가(무손실 정리 효과): 작은 실험으로 확인하고, 아니면 안 쓰는 객체 제거를 직접 구현한다.
- 유효 dpi 계산에 필요한 이미지 배치 행렬: PDFsharp의 내용 스트림 파서(`PdfEditor.ContentStream`)가 있으면 재사용, 없으면 PDFium 쪽 객체 경계로 대체한다.
