# 여러 창 + 탭 끌어내기·창 사이 탭 이동 (0.8.0) 설계

- 작성일: 2026-11-06
- 요청: 사용자. PDF-XChange Editor처럼 탭을 끌어 새 창을 만들고, 다른 창으로 옮길 수 있게 한다("내가 써보니 그게 편했다").
- 경로: 아키텍처(창·세션 소유 구조 변경). 이 문서는 스펙만이며 구현은 하지 않는다.
- 합의한 것: ① 마지막 탭/빈 창 동작 = A안(아래 3.4) ② 외부에서 연 파일 = 마지막 활성 창에 새 탭 ③ 구조 = 접근안 1(공유 문서 호스트 + 창별 뷰모델). PDF-XChange의 정확한 동작은 직접 확인하지 못해 알려진 동작과 사용자 요청을 근거로 정했으므로, 다른 부분은 검토 때 고친다.

## 1. 한눈에 (사용자 관점)

| 하고 싶은 일 | 동작 |
|---|---|
| 탭을 창 밖(탭 줄 아래·바깥)으로 끌어 놓기 | 놓은 자리에 새 창이 뜨고 그 탭이 거기로 옮겨진다 |
| 탭을 다른 창의 탭 줄에 끌어 놓기 | 그 창의 놓은 자리로 탭이 옮겨진다 |
| 저장 안 한(편집 중) 문서를 옮기기 | 아무것도 묻지 않고 그대로 옮긴다. 변경 내용·실행 취소 기록·복구 파일이 유지된다 |
| 탭 오른쪽 클릭 → "새 창으로 이동" | 끌기 없이도 같은 일을 한다(끌기가 어려운 사용자·시험용) |
| 창 닫기(X) | 그 창의 탭만 하나씩 저장 여부를 묻고 닫는다. 한 탭이라도 취소하면 창은 닫히지 않는다 |
| 파일 → 끝내기(Ctrl+Q) | 모든 창을 닫는다. 어느 창에서든 취소하면 거기서 멈춘다 |
| 탭이 하나뿐인 창에서 그 탭을 끌어 창 밖에 놓기 | 아무 일도 없다(새 창을 만들어도 같은 상황이므로). 다른 창의 탭 줄에 놓으면 합쳐지고 원래 창은 닫힌다 |

## 2. 목표와 비목표

**목표**
- 같은 프로세스 안에서 창을 여러 개 띄우고 탭(문서 세션)을 창 사이로 옮긴다.
- 옮겨도 문서 상태(변경, 실행 취소/다시 실행, 복구 파일, 파일 경로·이름)가 그대로다.
- 한 파일은 앱 전체에서 한 번만 열린다(어느 창에서 열려 있든 그 창을 앞으로 가져온다).
- 기존 단일 창 사용자는 달라지는 것이 없다(창이 하나일 때 동작·화면 동일).

**비목표 (이번 버전 제외)**
- 한 창 안에서 화면 나누기(좌우 비교).
- 다른 프로세스 사이 탭 이동. 의존성 추가 없음.
- 종료 후 창 배치(몇 개 창, 어느 탭이 어느 창) 복원. 비정상 종료 뒤 복구는 모두 첫 창에 탭으로 연다.
- 탭 끌 때 문서 미리보기 그림(고스트). 탭 제목 모양의 작은 표시만 한다.

## 3. 현재 구조 (조사 결과)

- `App.axaml.cs`가 `MainWindow`를 하나만 만들어 `desktop.MainWindow`로 둔다. 창을 닫으면 앱이 끝난다.
- `MainWindow`가 `MainWindowViewModel`을 직접 만들고, 같은 생성자에서 `PdfiumThread`(앱에 하나라고 주석), `SettingsStore`, `FileWorkflow`, `RecoveryCoordinator`, `SaveService`, `ReduceSizeWorkflow`, 인쇄 서비스를 만든다. 대화상자(`AvaloniaPrompts`, `AvaloniaRecoveryUi` 등)는 생성자에서 `this`(그 창)를 부모로 고정한다.
- `DocumentSession`(`PdfEditor.Document`)은 만들 때 받은 `PdfiumThread`를 평생 쥐고, PDFium 호출마다 그 스레드에서 실행 중인지 확인한다. 즉 **세션은 창이 아니라 PDFium 스레드에 묶여 있다.** 스레드가 하나로 공유되면 세션을 창 사이로 옮길 수 있다.
- `FileWorkflow._open`이 열린 세션 목록이고, "같은 경로가 이미 열렸나" 판단, 제목 없음 번호, 저장/닫기 확인이 여기 있다.
- `RecoveryCoordinator`는 `FileWorkflow.Saved/Released` 이벤트와 세션 `Id`(Guid)로 복구 파일을 관리한다. 창과는 무관하다(열린 세션 목록을 UI 스레드에서 받아 주기적으로 기록).
- `MainWindowViewModel`(약 940줄)은 탭 목록(`Documents`), 활성 탭, 리본·패널·줌 상태를 모두 쥔다. 정적 `DocumentTabViewModel.Settings/Appearance`는 이미 앱 공유다.
- 단일 인스턴스(`SingleInstance`, `Program`, `App`)는 받은 파일 경로를 **창 하나의** `ViewModel.OpenManyAsync`로 보낸다.
- 탭 끌기는 같은 탭 줄 안 순서 바꾸기뿐이다(`MainWindow.axaml.cs`의 `WireTabDrag`, `TabReorder`, `MoveDocument`). 탭 줄 밖으로 나간 포인터는 처리하지 않는다.
- 탭 하위 모델(썸네일·검색·주석·속성 등)은 `AttachPageEditing`이 탭마다 만들며 `_workflow`, `_prompts`, `_post`를 쥔다. `tab.Detach()`가 정리한다.

## 4. 설계

### 4.1 구조: 공유 문서 호스트 + 창별 뷰모델

```
App
 └ AppHost (앱에 하나)            ← 새로 만듦
     ├ PdfiumThread               (지금 MainWindow 안 → 여기로)
     ├ SettingsStore, AppearanceServices, SaveService
     ├ FileWorkflow               (열린 세션 목록 = 앱 전체)
     ├ RecoveryCoordinator        (타이머 하나, 앱 전체 세션 기록)
     ├ WindowRegistry             (열린 창 목록, 마지막 활성 순서)
     └ TabTransfer                (창 사이 탭 이동 조정)
 ├ MainWindow #1  ← MainWindowViewModel #1 (탭 목록·활성 탭·리본·패널 상태)
 ├ MainWindow #2  ← MainWindowViewModel #2
 └ ...
```

- **첫 창이 특별하지 않다.** 어느 창이든 마지막으로 남은 창이 닫히면 앱이 끝난다(ShutdownMode = OnLastWindowClose). 3.4의 "빈 화면으로 남는 마지막 창"은 사용자가 X로 닫아야 끝난다.
- `MainWindow`는 `AppHost`를 받아 만든다(`new MainWindow(host, ...)`). `MainWindowViewModel`은 창마다 하나이며 `Documents`는 그 창의 탭만 담는다.
- `FileWorkflow`는 대화상자 부모를 생성자 고정 대신 **"지금 부모 창을 알려 주는 함수"** 로 받는다(`AvaloniaPrompts(Func<Window>)`). 부모 = 그 작업을 시작한 창. 시작한 창을 알 수 없는 경우(복구 타이머 등)는 마지막 활성 창.
- 창 단위 상태(패널 보임·너비·리본 선택·줌)는 창마다 따로 쥔다. 새 창은 원래 창의 현재 값으로 시작한다. 설정 파일에는 마지막으로 바꾼 값이 저장된다(창 사이 경쟁은 마지막 기록 우선; `SettingsStore.Update`는 이미 읽고-고치고-쓰기).

### 4.2 세션 이동 방식 (핵심)

`DocumentSession` 객체는 **그대로 두고** 탭 모델만 새로 만든다. 직렬화·재열기는 하지 않는다.

1. 원래 창: 진행 중인 입력(본문 직접 편집 중이면 확정, 주석 텍스트 입력 중이면 확정)을 끝낸다. 그 뒤 현재 쪽·배율·스크롤·선택 쪽을 `TabViewState`로 담는다(이미 있는 `CaptureViewState`/`ApplyViewState`를 재사용).
2. 원래 창 `Documents`에서 탭을 빼고 `tab.Detach()`로 하위 모델(썸네일·검색·주석 패널 등)을 정리한다. **세션은 닫지 않고, `FileWorkflow.Release`도 부르지 않는다**(복구 파일이 지워지면 안 됨).
3. 대상 창: 같은 세션으로 `Activate(session)`처럼 새 탭 모델을 만들고 `TabViewState`를 적용해 놓은 자리에 넣고 활성화한다.
4. 원래 창이 비었고 두 번째 이후 창이면 닫는다(3.4). 닫기 확인은 하지 않는다(탭이 없음).

옮겨도 유지되는 것: 변경 여부, 실행 취소/다시 실행 기록, 복구 파일 연결, 제목·경로, 보던 쪽·배율. 사라지는 것(다시 시작): 검색 결과 강조, 썸네일 캐시(다시 그려짐), 고른 주석/개체, 활성 도구(기본 도구로).

### 4.3 끌기 동작

- 탭 줄 안: 지금과 같음(순서 바꾸기 + 놓을 자리 선 표시).
- 포인터가 탭 줄에서 세로로 일정 거리(예: 탭 높이) 벗어나면 "끌어내기" 상태가 된다. 이때 **화면 좌표**로 지금 포인터 아래에 어느 창의 탭 줄이 있는지 계속 확인한다(`WindowRegistry`가 창들의 탭 줄 사각형을 화면 좌표로 알려 준다).
  - 다른 창의 탭 줄 위: 그 창에 놓을 자리 선 표시 → 놓으면 이동.
  - 어느 창의 탭 줄도 아님: 놓으면 놓은 자리에 새 창(크기는 원래 창과 같되 화면 안으로 보정; 원래 창이 최대화면 보통 창 크기).
  - Esc: 취소(아무 일도 없음).
- 구현은 Avalonia의 창 간 DnD(OLE) 대신 **포인터 포획 + 화면 좌표 직접 판정**을 우선한다. 이유: 같은 프로세스 안이라 데이터 전달이 필요 없고, OLE 끌기는 다른 창 위에서 마우스를 놓친 채 끝나는 문제와 화면 배율 차이 문제가 있다. 이 선택은 7절의 0단계 스파이크에서 확인하고, 안 되면 DnD로 바꾼다.

### 4.4 창·탭 닫기와 종료 (A안)

- **탭 닫기:** 변경 있으면 묻고, 닫은 뒤 그 창이 비었으면: 두 번째 이후 창이면 창도 닫는다. 창이 하나뿐이면 지금처럼 빈 화면으로 남는다.
- **창 X:** 그 창 탭마다 `ConfirmCloseAsync`. 하나라도 취소하면 창은 그대로. 다 닫히면 창도 닫힌다.
- **끝내기(Ctrl+Q)·파일 > 끝내기:** 창을 활성 순서로 하나씩 닫는다. 어느 창이든 취소하면 남은 창은 그대로(이미 닫은 창의 탭은 이미 정리됨).
- **마지막 창:** 닫히면 `RecoveryCoordinator`, `PdfiumThread`를 정리하고 앱이 끝난다(지금 `OnClosing` 로직을 호스트로 이동). 이 정리는 창이 아니라 호스트 소유.
- 윈도우 종료(로그오프)로 모든 창이 한꺼번에 닫히는 경우도 위 순서로 처리한다. 취소하면 종료가 막힌다(현재 동작과 동일).

### 4.5 파일 열기와 중복

- `FileWorkflow.OpenAsync`가 이미 열린 경로면 기존 세션을 돌려준다. 호출한 창은 그 세션이 **자기 창 탭이면 전환**, **다른 창 탭이면 그 창을 앞으로 가져오고(최소화 해제) 탭을 활성화**한다. 소유 창은 `WindowRegistry.FindOwner(session)`으로 찾는다.
- 단일 인스턴스로 들어온 파일: `AppHost.OpenExternal(paths)`가 **마지막 활성 창**에 연다(최소화돼 있으면 복원). 열린 창이 없을 수는 없다(항상 1개 이상).
- 파일을 창에 끌어다 놓기(탐색기 → 창): 놓은 그 창에 연다.
- 복구 후 열기(앱 시작): 첫 창에 연다.
- 쪽 병합 등으로 만들어지는 새 세션(`PageCommands.SessionCreated`): 명령을 실행한 창에 연다.

### 4.6 복구·제목 없음·최근 문서

- 복구 파일은 세션 `Id`로 관리되어 창 이동과 무관하다. 타이머는 앱에 하나이고 열린 세션 전체(모든 창)를 기록한다. 스냅샷은 `FileWorkflow.OpenSessions`(앱 전체).
- "제목 없음 N" 번호는 `FileWorkflow`가 세므로 창이 여럿이어도 겹치지 않는다.
- 최근 문서는 설정 파일 하나(앱 공유).

## 5. 구조 변경 범위 (파일 단위)

| 영역 | 변경 |
|---|---|
| `App.axaml.cs`, `Program.cs` | `AppHost` 생성, 첫 창 생성, 종료 모드 변경, 단일 인스턴스 수신을 `AppHost.OpenExternal`로 |
| 새 `AppHost`, `WindowRegistry`, `TabTransfer` (App/Shell 또는 App/Hosting) | 공유 서비스 소유, 창 목록·활성 순서, 탭 이동 |
| `MainWindow.axaml.cs` | 서비스 생성 코드 제거(약 60줄) → 호스트에서 받기. `OnClosing`·탭 끌기 확장(끌어내기·화면 좌표 판정) |
| `MainWindowViewModel` | `Documents`/`Activate` 외 이동용 `DetachForTransfer`, `AcceptTransfer` 추가. 서비스 `Attach*`는 호스트가 만든 것을 받음. 나머지(리본·명령)는 그대로 |
| `FileWorkflow`/`AvaloniaPrompts`/인쇄·용량 줄이기·복구 UI | 부모 창을 고정하지 않고 "부모 창을 알려 주는 함수" 사용 |
| `DocumentTabViewModel` | `Detach` 시 세션을 닫지 않는 경로 확인(이미 분리됨; 시험으로 보증) |
| 탭 줄/리본 | 탭 오른쪽 클릭 메뉴에 "새 창으로 이동", 파일 메뉴에 "새 창" |
| `PdfEditor.Document`, `Pdf.Native` | 변경 없음(세션이 스레드에만 묶여 있고 창을 모름) |

변경하지 않는 것: 문서 편집·저장·PDFium 계층 전체.

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| `MainWindow` 생성자의 서비스 조립을 호스트로 옮기다 순서가 어긋나 기존 동작이 깨짐 | 1단계는 동작 변화 없이 옮기기만 하고 기존 시험 전체로 확인한 뒤 다음 단계로 간다 |
| 대화상자 부모가 엉뚱한 창(또는 이미 닫힌 창)이 되어 예외/먹통 | "부모 창을 알려 주는 함수"가 닫힌 창을 건너뛰고 마지막 활성 창을 쓴다. 닫힘 레이스 시험 |
| 세션을 옮기는 도중 PDFium 작업(렌더·저장·복구 기록)이 진행 중 | 세션은 같은 스레드에서 직렬 처리되므로 안전. 탭 모델이 정리되며 취소되는 렌더 요청이 새 탭에 새어 들어오지 않는지 시험. 저장·용량 줄이기 진행 중인 탭은 이동 금지(끌어내기 시작을 막고 안내) |
| 창이 닫히며 세션이 같이 해제됨(`Release`/`DisposeAsync`) | 이동 경로는 `Release`·`Dispose`를 호출하지 않는다. 시험: 이동 뒤 복구 파일 존재, 저장 가능, 실행 취소 가능 |
| 화면 배율이 다른 모니터 사이 끌기에서 좌표 오차 | 화면 좌표는 물리 픽셀로 통일해 계산. 2개 모니터(100%/150%) 수동 시험 항목으로 둔다 |
| 끌기 중 포인터 포획이 창 밖에서 풀림 | 7절의 0단계 스파이크에서 먼저 확인. 실패하면 Avalonia `DragDrop.DoDragDrop`으로 전환(스펙 갱신) |
| 창 사이 설정(패널 너비) 덮어쓰기 | 마지막 기록 우선으로 문서화. 큰 위험 아님 |
| 두 창이 같은 복구 폴더·설정 파일을 동시에 씀 | 이미 프로세스 하나가 쓰던 구조이고 복구 타이머는 앱에 하나만 둔다 |
| 대형 변경이라 한 번에 넣으면 회귀 추적이 어려움 | 7절의 단계로 쪼개 매 단계마다 실행 가능하고 시험이 통과하는 상태를 유지 |

## 7. 구현 단계 (계획 문서에서 상세화)

0. **스파이크(버릴 코드):** 두 번째 창을 띄우고 포인터 포획 + 화면 좌표로 탭 줄 판정이 되는지, 모니터 경계·배율 확인. 결과로 4.3 선택 확정.
1. **호스트 추출(동작 변화 없음):** `AppHost`로 서비스 소유 이동, 창 하나. 기존 시험 모두 통과.
2. **다중 창 기반:** 파일 > "새 창", `WindowRegistry`, 창 닫기·끝내기 규칙, 부모 창 함수, 단일 인스턴스를 마지막 활성 창으로.
3. **탭 이동(명령):** 탭 오른쪽 클릭 "새 창으로 이동"과 "창 사이 이동"을 명령으로 먼저 구현(`TabTransfer`). 세션 보존 시험 전부.
4. **끌어내기 UI:** 끌기 → 새 창/다른 창 탭 줄에 놓기, 놓을 자리 표시, Esc 취소.
5. **마무리:** 배율 다른 모니터, 창 위치 보정, README(ko/en) 설명, 수동 시험표.

## 8. 시험 계획

**자동 (xUnit, 화면 없이)**
- `WindowRegistry`: 마지막 활성 순서, 닫힌 창 제외, 소유 창 찾기, 마지막 창 규칙.
- 탭 이동 순수 계산: 놓을 자리 판정(화면 좌표 → 창/자리), 단독 탭 이동 규칙, `TabReorder` 재사용.
- `MainWindowViewModel`(가짜 워크플로로): 이동 뒤 원래 창 `Documents`에서 빠지고 대상 창에 같은 `DocumentSession` 참조로 생기는지, 세션이 `Dispose`/`Release` 안 되는지, 더티 상태·실행 취소 기록 유지.
- `FileWorkflow`: 같은 경로 중복 열기가 창과 무관하게 한 세션을 돌려주는지, 부모 창 함수가 닫힌 창을 건너뛰는지.
- 복구: 이동 뒤에도 복구 파일이 남고 저장하면 지워지는지.
- Avalonia.Headless(`PdfEditor.App.Tests`에 이미 있음)로 창 두 개를 띄워 이동·닫기 규칙 확인.

**수동 (실제 화면, 사용자 시험표)**
1. 탭 2개 이상 → 하나를 창 밖으로 끌기 → 새 창 위치·크기, 원래 창 유지.
2. 다른 창 탭 줄에 놓기(앞/중간/끝 자리), 놓을 자리 선 표시.
3. 저장 안 한 문서를 이동 → 묻지 않음, 저장·실행 취소 정상, 자동 복구 파일 유지(`%LOCALAPPDATA%\SedolPDF`).
4. 단독 탭 끌기: 새 창 안 생김 / 다른 창에 합치면 원래 창 닫힘.
5. 창 X로 닫기(변경 있는 탭 포함, 취소), 끝내기, 마지막 탭 닫기(두 번째 창 닫힘, 마지막 창 빈 화면).
6. 탐색기에서 PDF 더블클릭 → 마지막 활성 창에 열림, 이미 열린 파일은 그 창이 앞으로.
7. 모니터 2개(배율 다름)에서 끌기.
8. 인쇄·용량 줄여 저장·다른 이름으로 저장 대화상자가 올바른 창 위에 뜨는지.
9. 비정상 종료(작업 관리자로 끝내기) 후 재시작 → 복구 대화상자 → 모두 첫 창에 열림.

## 9. 미결정 / 후속

- 끌기 구현 방식(포획+화면 좌표 vs DnD)은 0단계 결과에 따른다.
- 종료 후 창 배치 복원은 이번 비목표. 필요하면 별도 후보.
- 창 제목 표시줄/작업 표시줄에서 창을 구분하는 문구(열린 문서 이름 또는 "SedolPDF - 문서명")는 구현 계획에서 현재 `FileName` 표시와 맞춘다.
