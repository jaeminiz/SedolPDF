# 텍스트 한 줄 부분 편집 (PDF-XChange식) 설계

## 배경 (사용자 검수 2026-11-04)
- 8372 PDF의 "PLAN HISTORY"에 " DD"를 붙이면 지금은 줄 전체가 앱 글꼴(Noto Sans) 일반 굵기로 바뀐다. 원본 글자가 서브셋이라 "D"가 없기 때문이다.
- PDF-XChange는 원본 글 객체를 그대로 두고 새 글자만 설치된 같은 글꼴(Arial Unicode MS)로 뒤에 붙인다. 굵게는 사용자가 켜면 원본과 같아진다.
- Acrobat은 설치된 글꼴로 줄 전체를 다시 쓴다(원본이 바뀜).

## 목표
1. 바뀌지 않은 글자는 원본 글 객체 그대로 둔다(글꼴·모양 100% 보존).
2. 바뀌거나 새로 들어간 글자만 새 글 객체로 그린다. 크기·색·기준선을 원본에 맞춘다.
3. 새 글자의 굵기·기울임은 원본에서 자동으로 알아낸다(굵은 글꼴 이름, 겹쳐 찍은 글, 렌더 모드 2).

## 범위
- **1단계(이번)**: 한 줄 편집(`ObjectToolController.ReplaceTextAsync` / `TextEditPlanner.PlanReplace`). 공통 앞부분(및 뒷부분)을 원본 객체에 남기고 가운데만 새 글 객체로. 새 글자는 앱 글꼴 + 원본에서 알아낸 합성 굵게·기울임.
- **2단계(별도 결정)**: 새 글자를 PC에 설치된 같은 글꼴(Arial 등)로. 앱의 글꼴 파이프라인은 CFF(OpenType)만 다뤄서 Windows의 TrueType(Arial)을 쓰려면 TrueType 내장·서브셋(FontFile2, CIDFontType2) 지원이 새로 필요하다. 내장 허용(fsType) 확인 포함. 이번 범위 밖.
- 문단 편집, 폼 안 글 편집은 이번 범위 밖.

## 설계 (1단계)
1. **차이 계산**: `TextDiff.Common(string oldText, string newText) -> (int Prefix, int Suffix)` — 앞·뒤 공통 글자 수(겹치지 않게, 줄 전체가 같으면 변경 없음). 순수 함수.
2. **원본 유지 조각**: 공통 앞부분 P(길이 ≥ 1)이면 원본 객체를 `InsertTextLikeEdit`로 P만 남긴 글(원래 글꼴, `OriginalFontReplacer.Verify` 통과)로 바꾸고, 가운데·뒷부분만 새 객체로. 서브셋 글자만 있으면 기존 동작(전체를 원본 글꼴로)과 같다.
3. **새 조각 위치**: 남긴 앞부분의 오른쪽 끝(`Bounds.Right`, 회전 쪽은 글 방향 기준)에서 이어 붙인다. 크기·색은 원본, 기준선은 원본과 같다. 뒷부분이 있으면 뒷부분도 원본 위치에서 같은 방식으로 이어 붙이되 1단계에서는 앞부분만(뒷부분이 다르면 전체를 지금처럼 다시 쓴다) — 위험을 줄이기 위해.
4. **굵기 자동 판별**: 이미 있는 `AppFontCatalog.Classify`(이름·플래그) + 겹쳐 찍은 글(`ResolveOverlappedAsync`의 shadows) + 렌더 모드 2 → `AppFontChoice.SyntheticBold`. 겹쳐 찍은 글은 0.05em 선 굵기(현재 구현).
5. **확정·취소**: 기존과 같다. 실행 취소 한 번(`ContentEditCommand` 하나).

## 검증
- `TextDiff` 단위 시험(앞 공통, 전부 같음, 전부 다름, 한글, 서로게이트 쌍).
- 편집 시험: 서브셋에 없는 글자를 뒤에 붙이면 원본 객체가 비활성화되지 않고(`DeactivateEdit` 없음 또는 앞부분만 남김) 새 객체 하나가 추가된다. 겹친 굵은 글에 붙이면 새 객체가 굵다.
- 실제 화면: 8372 PDF "PLAN HISTORY" + " DD"에서 앞부분 글꼴 유지, 새 글자 굵게 확인(검증 필요: 회전 쪽).

## 위험
- 원본 객체에 SetText로 앞부분만 남길 때 글자 간격(Tc/Tz, 커닝)이 줄 전체와 달라질 수 있다 → 남긴 앞부분의 `Bounds.Right`를 실제로 재서 이어 붙이고, 어긋나면 기존 방식(전체 다시 쓰기)으로 되돌린다.
- 새 조각이 앱 글꼴이라 글자 모양이 원본과 다르다(2단계에서 설치 글꼴로 줄인다).
