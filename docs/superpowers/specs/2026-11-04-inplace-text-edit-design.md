# 텍스트 편집 제자리 개편 (X-Change·Acrobat식) 설계

## 배경
- 0.5.0에서 "텍스트 편집"은 글을 누르면 흰 배경 팝업 편집 창(한 줄: `FreeTextEditor`, 문단: `ParagraphEditorPopup`)이 원본 위에 덮여 열린다.
- 사용자 샘플(8372-8372416-0.PDF 1쪽)에서 "PLAN HISTORY"를 누르면 편집 칸이 비어 보이고 원본이 가려져 글이 사라진 것처럼 보인다.
- PDF-XChange·Acrobat은 도구를 켜면 편집 가능한 글 조각 상자를 미리 보이고, 글은 가려지지 않은 채 제자리에서 고친다.

## 목표
1. 글이 편집 중에도 항상 보인다(5번 증상 제거).
2. 도구를 켜면 편집 가능한 글 조각에 옅은 상자가 미리 보이고, 마우스를 올리면 강조된다.
3. 편집 칸이 원본 글의 위치·크기·줄 간격·글자색에 맞춰 제자리에 겹친다.

## 범위 밖
- 편집 중 원본을 렌더에서 지우는 방식, 자체 편집기(캐럿·IME 직접 구현). 확정·취소·계획 로직은 바꾸지 않는다.

## 설계
1. **원인 재현·수정(선행)**: 위 샘플로 한 줄 편집 칸이 비어 보이는 원인을 재현해 먼저 고친다. 회귀 시험 추가.
2. **미리 보이는 상자**: `ToolKind.EditText`일 때 보이는 쪽의 `PageObjectIndex` 텍스트 항목 경계를 `DocumentView` 오버레이에 옅은 선으로 그린다. 호버 조각은 진한 선. 렌더 캐시는 건드리지 않는다.
3. **제자리 편집 칸**: 편집 칸 배경을 반투명 흰색으로, 글자색은 원본 색(모르면 검정). 위치·글자 크기는 현재 계산(`PlacementRect`, 글 높이 기반)을 원본 경계에 맞게 보정. 점선 문단 상자·줄 포함/제외 단추 유지.
4. **확정·취소**: Enter/Ctrl+Enter, 바깥 클릭, Esc 그대로. `ReplaceTextAsync`, `ParagraphController` 변경 없음.
5. **문구**: 새 UI 문구는 ko/en resx에 함께 추가.

## 검증
- 단위/UI 시험: 편집 칸이 비지 않음, 칸 위치가 원본 경계와 일치, 호버 상자 그리기.
- 실제 화면: 샘플 1쪽("PLAN HISTORY", "NOTE" 문단)과 한글 샘플에서 직접 확인(별도 `-o` 폴더 빌드).

## 위험
- 투명 겹침은 시스템 글꼴과 원본 글꼴이 달라 글자가 약간 어긋나 보일 수 있다 → 반투명 배경 농도로 가독성을 확보하고, 모양 차이는 알려진 한계로 둔다.
