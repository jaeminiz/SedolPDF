- 화면 시안: `docs/design/ui-mockup-v2.html` (채택안), `docs/design/ui-mockup-v1.html` (초기 비교안)

## 1. 목적과 성공 기준

### 1.1 해결할 문제
- PDF-XChange Editor는 주석 편집 기능이 뛰어나지만, 화면 디자인이 복잡하고 시각적 잡음이 많습니다.
- Foxit·Acrobat 수준의 편집 기능을 갖춘 **오픈소스** Windows PDF 에디터가 필요합니다.

### 1.2 목표
- GitHub에 공개하는 **범용 오픈소스 제품**으로, 불특정 다수가 Foxit 대신 쓸 수 있는 수준을 목표로 합니다.
- PDF-XChange 수준의 주석 편집 기능을 Windows 11 디자인 언어(Fluent)로 정리한 화면에 담습니다.

### 1.3 개발 체제
- 사용자가 기획과 검수를 맡고, 코드는 Claude가 주로 작성합니다.
- 따라서 기술 스택은 **언어 1개, 단순한 빌드, 쉬운 디버깅**을 우선합니다.

### 1.4 1차 성공 기준
1. 2절의 기능이 동작합니다.
2. 이 앱에서 저장한 주석이 Adobe Acrobat Reader, PDF-XChange, Foxit, Chrome에서 같은 모양으로 보입니다.
3. 텍스트 상자·타자기·설명선 등에 쓴 한글이 다른 뷰어에서도 깨지지 않습니다.
4. A1 크기 도면이나 수백 페이지 문서도 열고 스크롤할 수 있습니다. 성능 목표 (기술 검증 S4 실측 기반, 2026-10-15):
   - 512×512 타일 p95 100 ms 이하 (밀집한 A1 도면 1배 실측 61 ms)
   - A1 도면 첫 화면 표시 0.5초 이하
   - 300쪽 문서를 100% 배율로 끝까지 훑는 데 3초 이내, 작업 집합 메모리 400 MB 미만
   - 확대·스크롤 때 회색 빈칸이 눈에 띄지 않게 (이전 배율 타일 임시 표시 + 화면 밖 한 타일 미리 렌더, 정량 기준은 M1에서 정함)
5. 앱은 기업에서도 무료로 쓸 수 있어야 하고, 모든 의존성의 라이선스도 같은 조건을 만족해야 합니다 (3절).

## 2. 1차 기능 범위

### 2.1 문서·페이지 (M1)
| 기능 | 구현 (PDFium API) |

| 새 PDF 생성 | `FPDF_CreateNewDocument`, `FPDFPage_New` |
| 병합 | `FPDF_ImportPages` / `FPDF_ImportPagesByIndex` |
| 페이지 추가·삽입 | `FPDFPage_New`, `FPDF_ImportPages` |
| 페이지 삭제 | `FPDFPage_Delete` |

### 2.2 주석 (M2·M3)

**AP 정책:** 모든 주석의 화면 표시 모양(Appearance Stream, 이하 AP)은 `Appearance` 모듈의 Painter가 직접 만듭니다. PDFium의 AP 생성 기능은 쓰지 않습니다. 화면과 저장 결과가 같은 코드에서 나와야 하기 때문입니다(4.2-3). 마일스톤은 작업량으로 나눕니다. M2는 모양이 단순한 유형, M3는 선 끝 모양·폰트·묶음 처리가 필요한 유형입니다.

| 기능 | PDF 주석 유형 (ISO 32000) | 비고 | 마일스톤 |
|---|---|---|---|
| 연필 | Ink | | M2 |
| 지우개 (연필 주석의 일부 지우기) | Ink 경로 분할·삭제 | | M2 |
| 텍스트 강조 | Highlight | | M2 |
| 영역 강조 | Highlight (텍스트 대신 사각 영역 지정) *(검증 V1)* | | M2 |
| 밑줄 | Underline | | M2 |
| 취소선 | StrikeOut | | M2 |
| 스티커 메모 | Text + Popup | | M2 |
| 사각형·타원 | Square, Circle | | M2 |
| 선·화살표 | Line (선 끝 모양 LE 지정) | | M3 |
| 폴리라인·다각형 | PolyLine, Polygon | | M3 |
| 클라우드 | Polygon/Square + 클라우드 테두리 효과 (`/BE <</S /C>>`) | | M3 |
| 텍스트 상자 | FreeText | 한글 폰트 포함 (S1) | M3 |

| 텍스트 삽입 | Caret | | M3 |
| 텍스트 바꾸기 | StrikeOut + Caret 묶음 (IRT로 연결, RT = Group) | | M3 |
| 스탬프 (기본·이미지·사용자 정의) | Stamp (`FPDFAnnot_AppendObject`로 내용 삽입) | | M3 |
| 파일 첨부 | FileAttachment (`FPDFAnnot_AddFileAttachment`) | | M3 |

**모든 주석에 공통으로 들어가는 기능:**
- 선택, 이동, 크기 조절
- 속성 편집: 색상, 투명도, 선 두께, 글꼴
- 실행 취소 / 다시 실행
- 작성자·작성 시각 기록
- 상태 지정과 답글

**주석 관리 기능 (M3):**
- **코멘트 목록:** 패널에 주석을 나열하고, 필터·정렬·답글·상태 변경을 지원합니다.
- **주석 스타일:** 자주 쓰는 색·선 두께·글꼴 조합을 이름 붙여 저장하고 재사용합니다.
- **주석 가져오기·내보내기:** XFDF 형식(주석만 담는 XML 파일)으로 주고받습니다. FDF 형식은 검증 V3 결과에 따라 결정합니다.
- **주석 요약:** 페이지별 코멘트를 정리한 보고서를 새 PDF로 만듭니다.

### 2.3 수정 (M4·M5)
- **M4 — 객체 단위 편집:**
  - 기존 텍스트 한 줄의 내용 교체
  - 이미지·도형의 이동, 크기 변경, 삭제
  - 새 텍스트·이미지·도형 추가
  - 원본 폰트에 없는 글자를 쓰면 앱에 포함된 폰트로 대체
- **M5 — Acrobat 방식 문단 편집:**
  1. 흩어진 텍스트 줄 객체를 좌표·줄 간격·글꼴을 보고 문단 상자로 묶습니다(추정).
  2. 편집하면 그 상자 안에서만 줄바꿈을 다시 맞춥니다. 다른 상자나 다음 페이지로 넘어가지 않습니다.
  3. 원본 폰트를 쓸 수 없으면 비슷한 폰트로 대체해 편집합니다.
  4. 저장할 때 다시 개별 텍스트 객체로 풀어서 기록합니다.
  - 표나 도면 표제란에서는 추정이 틀릴 수 있습니다. 사용자가 상자를 나누거나 합치는 기능이 필요한지는 M5 설계 때 결정합니다.

### 2.4 1차 제외 (2차 이후)

- 전자서명

- 미디어 주석 (비디오·사운드·3D), 소리 주석, 텍스트 교정, 자유형 강조
- 보호(암호화 설정), 공유, 리뷰 기능. 암호가 걸린 PDF를 열고 편집하는 것은 1차 범위입니다(8.2절)
- 책갈피·레이어·첨부 편집 (1차에서는 읽기·이동만)
- 다크 모드
- Mac 스타일 테마 (시안은 `ui-mockup-v2.html`에 참고용으로 남겨 둠)

## 4. 아키텍처 (승인됨)

### 4.1 모듈 구성
| 모듈 | 역할 | 의존 대상 |
|---|---|---|
| `Pdf.Native` | PDFium P/Invoke 래퍼. 모든 호출을 **전용 스레드 하나**에서 순서대로 실행합니다 (PDFium은 여러 스레드에서 동시에 쓸 수 없음). | PDFium |
| `Document` | 문서·페이지·주석을 담는 자체 데이터 모델, 실행 취소/다시 실행(명령 스택), 선택 상태 | Pdf.Native |
| `Appearance` | 주석 모델을 AP(PDF 그리기 명령 + 폰트 등 자원)로 변환. 한글 폰트는 쓴 글자만 뽑아 포함 | Document |
| `Pages` | 새 문서 생성, 병합, 페이지 삽입·삭제·회전·순서 변경 | Pdf.Native |
| `TextEdit` | 객체 편집(M4), 문단 편집(M5) | Document, Appearance |
| `Exchange` | 주석 가져오기·내보내기(XFDF), 주석 요약 PDF 생성 | Document, Appearance |
| `App` | Avalonia UI: 리본, 패널, 문서 화면 | 위 전체 |

### 4.2 핵심 설계 결정
1. **편집 중에는 자체 모델이 기준입니다.** 파일을 열 때 PDF의 주석을 `Document` 모델로 읽어 오고, 저장할 때 PDF에 다시 씁니다.
2. **화면을 두 층으로 나눠 그립니다.**
   - PDF 본문은 PDFium이 주석을 뺀 상태로 화면 조각(타일) 단위로 그립니다.
   - 주석은 그 위에 Avalonia가 별도 층으로 그립니다.
   - 그래서 주석을 끌어 옮겨도 페이지 전체를 다시 그리지 않습니다.
3. **화면용 그리기와 저장용 그리기가 같은 코드를 씁니다.** 주석 모양을 계산하는 코드는 하나만 두고(`IAnnotationPainter` 같은 추상화), 출력만 두 갈래로 나눕니다. 하나는 화면(Avalonia `DrawingContext`)에 그리고, 다른 하나는 PDF AP로 씁니다. 이렇게 해야 화면과 저장 결과가 어긋나지 않습니다. PDFium의 AP 자동 생성은 쓰지 않습니다.
4. **지원하지 않는 주석도 화면에 보여야 합니다.** 본문을 주석 없이 그리면, 읽기 전용으로 보존하는 주석(Link, Widget, Squiggly 등)까지 사라집니다. 렌더링하는 동안에만 지원 유형 주석에 Hidden 플래그를 붙이고 `FPDF_ANNOT`로 그린 뒤 원래 플래그로 되돌립니다. 검증 S4에서 확정했습니다 (지원 유형은 사라지고 미지원 유형은 그려지며, 저장 파일에 플래그가 남지 않음).
5. **원본 주석 딕셔너리를 보존합니다.** 지원하는 유형이라도 모델이 모르는 키(다른 뷰어 전용 키 등)가 있을 수 있습니다. 저장할 때는 원본 딕셔너리를 그대로 두고, 모델에서 바뀐 키와 AP만 덮어씁니다.

## 5. 화면 설계 (승인됨)

- **디자인 언어:** Windows 11 Fluent
  - 바탕: 반투명 Mica
  - 패널: 바탕 위에 카드 형태로 띄움
  - 아이콘: 단색 선 아이콘
  - 강조색: Windows 기본 파랑 `#005FB8`
- **창 조작 버튼:** Windows 관례대로 오른쪽
- **툴바 버튼 이름:** 항상 표시
- **다크 모드:** 2차 이후

### 5.1 화면 구성 (위에서 아래로)
1. **제목 표시줄:**

4. **본문 (왼쪽에서 오른쪽):**
   - 패널 전환 아이콘 세로 막대: 썸네일, 책갈피, 코멘트, 첨부, 레이어, 검색

## 8. 데이터 흐름·저장·오류·테스트 (승인됨, 2026-10-15)

### 8.1 주석 데이터 흐름
- **열기:** PDFium으로 주석을 읽어 `Document` 모델로 변환합니다. 모델의 각 주석은 원본 PDF 주석을 가리키는 참조(페이지 번호 + 주석 인덱스 또는 `/NM`)를 함께 가집니다.
- **편집:** 모든 변경은 명령(Command) 객체로 실행해서 실행 취소 스택에 쌓습니다. 주석과 페이지 조작(M1)이 같은 스택을 씁니다.
- **저장:** 모델과 원본의 차이를 계산해 PDF에 반영합니다.
  1. 삭제된 주석을 제거합니다.
  2. 새 주석을 만듭니다.
  3. 수정된 주석은 바뀐 키만 덮어씁니다(4.2-5).
  4. 생성·수정된 주석의 AP를 Painter로 새로 씁니다.
  5. 8.2의 저장 절차로 파일에 기록합니다.
- **지원하지 않는 유형:** 원본 PDF의 주석 중 모델이 지원하지 않는 유형은 읽기 전용으로 보존합니다. 화면에는 표시하고(4.2-4), 저장할 때는 손대지 않습니다.

### 8.2 저장과 오류 처리
| 항목 | 동작 |
|---|---|
| 기본 저장 방식 | 전체 저장(`FPDF_SaveAsCopy`, 증분 플래그 없음). 증분 저장은 v1에서 쓰지 않습니다. |
| 원본 보호 | ① 같은 폴더의 임시 파일(`~<이름>.tmp`)에 씁니다. ② PDFsharp 후처리를 이 임시 파일에 적용합니다 (S1에서 2단계 저장으로 확정: 한글 FreeText 등 폰트 자원이 필요한 AP는 PDFium만으로 만들 수 없음). 후처리할 것이 없으면 건너뜁니다. 암호 PDF에서 이 단계가 어떻게 동작하는지는 V6과 함께 확인합니다 *(검증 필요)*. ③ 임시 파일을 PDFium으로 다시 열어 페이지 수와 주석 수를 확인합니다. ④ `File.Replace`로 원본과 교체합니다. 어느 단계든 실패하면 임시 파일을 지우고 원본을 그대로 둔 채 오류를 알립니다. |
| 자동 복구 | N분(기본 5분, 설정에서 변경)마다 `%LOCALAPPDATA%\<앱 이름>\Recovery`에 편집 상태를 기록합니다. 기록하는 것은 원본 경로, 원본 해시, 모델 스냅숏입니다. 원본 파일은 건드리지 않습니다. 정상 종료하거나 저장하면 해당 복구 파일을 지웁니다. 다음 실행 때 복구 파일이 남아 있으면 복구할지 묻습니다. 원본 해시가 바뀌었으면 그 사실을 함께 알립니다. |
| 암호가 걸린 PDF | 열기 암호를 물어 엽니다. 편집은 허용합니다. 저장할 때 암호화가 유지되는지는 검증 V6으로 확인합니다. 유지되지 않으면 "암호화가 해제된다"고 경고하고, 원본 덮어쓰기는 막고 다른 이름으로 저장만 허용합니다. 권한 암호(인쇄·수정 제한)는 표시만 하고, 제한은 PDFium의 권한 플래그를 따릅니다 *(검증 필요)*. |
| 손상된 PDF | PDFium이 자동 복구해서 열면 "파일이 손상되어 복구한 상태로 열었다"고 알리고, 다른 이름으로 저장하기를 권합니다(감지 방법은 검증 V8). 열 수 없으면 `FPDF_GetLastError` 코드를 사용자 메시지로 바꿔 보여 줍니다. |
| PDFium 호출 오류 | `Pdf.Native`가 오류 코드를 예외로 바꿉니다. UI는 작업 단위로 예외를 잡고, 문서 상태는 명령 실행 전 상태로 되돌립니다. |

### 8.3 테스트 전략
| 종류 | 내용 | 실행 |
|---|---|---|
| 단위 테스트 | 모델, 명령/실행 취소, Painter의 그리기 명령 출력 | xUnit, CI 자동 |
| 왕복 테스트 | 주석 생성 → 저장 → 다시 열기 → 모델 비교. 알 수 없는 키가 보존되는지 포함 | xUnit, CI 자동 |
| 렌더링 테스트 | 저장 결과를 PDFium으로 그려 기준 PNG와 비교. 픽셀 허용오차를 두고, 기준 이미지는 `tests/fixtures/baseline/`에 둠 | xUnit, CI 자동 |
| 뷰어 호환성 | Acrobat Reader, PDF-XChange, Foxit, Chrome에서 같은 샘플을 열어 확인 | 수동, `docs/checklists/viewer-compat.md` |

- 테스트 샘플 PDF는 테스트 코드로 생성하거나 공개 라이선스 파일만 씁니다.
- 대용량 성능(S4)은 별도 벤치마크 프로젝트로 측정하고 CI에는 넣지 않습니다.
