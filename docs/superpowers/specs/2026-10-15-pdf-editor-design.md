- 상태: **1~8절 승인 완료** (2026-10-15). 기술 검증 S0~S4 결과를 1.4·3·4.2·6·8.2절에 반영했습니다 (2026-10-15).
- 화면 시안: `docs/design/ui-mockup-v2.html` (채택안), `docs/design/ui-mockup-v1.html` (초기 비교안)

## 1. 목적과 성공 기준

### 1.1 해결할 문제
- PDF-XChange Editor는 주석 편집 기능이 뛰어나지만, 화면 디자인이 복잡하고 시각적 잡음이 많습니다.
- Foxit·Acrobat 수준의 편집 기능을 갖춘 **오픈소스** Windows PDF 에디터가 필요합니다.

### 1.2 목표
- GitHub에 공개하는 **범용 오픈소스 제품**으로, 불특정 다수가 Foxit 대신 쓸 수 있는 수준을 목표로 합니다.
- PDF-XChange 수준의 주석 편집 기능을 Windows 11 디자인 언어(Fluent)로 정리한 화면에 담습니다.

### 1.3 개발 체제
- 사용자가 기획과 검수를 맡고, 코드는 Claude가 주로 작성합니다.
- 따라서 기술 스택은 **언어 1개, 단순한 빌드, 쉬운 디버깅**을 우선합니다.

### 1.4 1차 성공 기준
1. 2절의 기능이 동작합니다.
2. 이 앱에서 저장한 주석이 Adobe Acrobat Reader, PDF-XChange, Foxit, Chrome에서 같은 모양으로 보입니다.
3. 텍스트 상자·타자기·설명선 등에 쓴 한글이 다른 뷰어에서도 깨지지 않습니다.
4. A1 크기 도면이나 수백 페이지 문서도 열고 스크롤할 수 있습니다. 성능 목표 (기술 검증 S4 실측 기반, 2026-10-15):
   - 512×512 타일 p95 100 ms 이하 (밀집한 A1 도면 1배 실측 61 ms)
   - A1 도면 첫 화면 표시 0.5초 이하
   - 300쪽 문서를 100% 배율로 끝까지 훑는 데 3초 이내, 작업 집합 메모리 400 MB 미만
   - 확대·스크롤 때 회색 빈칸이 눈에 띄지 않게 (이전 배율 타일 임시 표시 + 화면 밖 한 타일 미리 렌더). 정량 기준(M1 확정, 2026-10-16): 300쪽 100% 연속 스크롤에서 프레임 평균 회색 비율(뷰포트 안 페이지 면적 중 아무 그림으로도 안 덮인 비율, 8px 격자 표본) 2% 이하, 회색이 연속으로 보이는 시간 최대 250 ms 이하. M1 실측: 두 값 모두 0 (A1 첫 화면·300쪽 작업 집합은 처음 0.7 s·424 MB로 미달이었으나 M1 마무리 검토에서 고쳐 0.44~0.47 s·362~374 MB로 통과 — `docs/validation/2026-10-m1-results.md` "M1 마무리 검토")
5. 앱은 기업에서도 무료로 쓸 수 있어야 하고, 모든 의존성의 라이선스도 같은 조건을 만족해야 합니다 (3절).

### 2.2 주석 (M2·M3)

**AP 정책:** 모든 주석의 화면 표시 모양(Appearance Stream, 이하 AP)은 `Appearance` 모듈의 Painter가 직접 만듭니다. PDFium의 AP 생성 기능은 쓰지 않습니다. 화면과 저장 결과가 같은 코드에서 나와야 하기 때문입니다(4.2-3). 마일스톤은 작업량으로 나눕니다. M2는 모양이 단순한 유형, M3는 선 끝 모양·폰트·묶음 처리가 필요한 유형입니다.

**M3a 구현 비고 (2026-10-17):** 위 표의 M3 유형 가운데 선·폴리라인·다각형·클라우드·텍스트 상자·타자기·설명선·텍스트 삽입·텍스트 바꾸기·스탬프·파일 첨부는 **M3a에서 구현**했습니다(주석 관리 기능과 상태·답글은 M3b). PDFium이 만들 수 없는 유형(Line·PolyLine·Polygon·FreeText·Caret·Stamp·FileAttachment)과 Popup·클라우드 테두리 효과·이미지·첨부 바이트는 **저장할 때 PDFsharp 패치 단계**가 PDF에 씁니다(3절, 8.2절). 알려진 한계: 원본(다른 프로그램이 만든) FreeText를 손대면 서식이 우리 모양으로 바뀜(글꼴·배경 등), 형광펜 곱하기 혼합 없음, 암호가 걸려 패치할 수 없는 문서에서는 위 새 유형 도구를 끄고 원본은 읽기 전용, 원본 Stamp·FileAttachment·원 모양 클라우드·세부 옵션이 있는 Line은 읽기 전용. 자세한 내용은 `docs/validation/2026-10-m3a-results.md`.

**모든 주석에 공통으로 들어가는 기능:**
- 선택, 이동, 크기 조절
- 속성 편집: 색상, 투명도, 선 두께, 글꼴
- 실행 취소 / 다시 실행
- 작성자·작성 시각 기록 (M2: `/T` 작성자, `/CreationDate`, `/M`, `/Subj`, `/NM`)
- 상태 지정과 답글 (**M3b에서 구현(2026-10-18)**, 코멘트 목록과 함께. M2는 원본의 답글·상태 주석을 읽기 전용으로 보존만 했습니다)

**주석 관리 기능 (M3b, 구현 2026-10-18):**
- **코멘트 목록:** 왼쪽 패널에 모든 주석(편집 가능한 것 + 다른 프로그램이 만든 읽기 전용 원본)을 나열하고, 필터(종류·작성자·상태·쪽 범위·글자 검색)·정렬(쪽·시각·작성자·종류)·답글·상태 변경(없음·승인·거부·취소·완료)·삭제·위치로 이동을 지원합니다. 답글은 Text 주석 + `/IRT`, 상태는 거기에 `/State`·`/StateModel /Review`이고 쪽 위에는 아이콘을 그리지 않습니다(결정 B1). 부모를 지우면 답글·상태도 함께 지워지고 실행 취소로 함께 돌아옵니다.
- **주석 스타일:** 자주 쓰는 색·채우기·불투명도·선 두께·글자 크기·선 끝·클라우드 조합을 이름 붙여 저장하고(설정 파일, 기본 3개) 선택한 주석이나 켜진 도구에 적용합니다. 한계: 스타일로 채우기를 없앨 수 없고, 도구 스타일에는 글자 크기·선 끝·클라우드가 들어가지 않습니다.
- **주석 가져오기·내보내기:** XFDF 형식(주석만 담는 XML 파일)으로 주고받습니다. **FDF 형식은 만들지 않기로 결정**(XFDF만으로 충분, 필요하면 2차). 가져오기는 같은 `/NM`이면 기존 주석을 바꾸고(읽기 전용 원본은 제외), 모르는 요소·잘못된 쪽·깨진 좌표는 건너뛰어 개수·이유를 알리며, 전체가 실행 취소 한 번입니다. 다른 뷰어와의 호환(V3)은 *검증 필요*.
- **주석 요약:** 쪽별 코멘트를 정리한 보고서(쪽 그림 + 번호 + 내용·답글 목록, 한글, A4)를 새 PDF로 만듭니다. 쪽 그림은 패치된 사본에서 그려 선 같은 패치 단계 주석도 보입니다(4.2-6).

자세한 내용·한계는 `docs/validation/2026-10-m3b-results.md`.

### 2.3 수정 (M4·M5)
- **M4 — 객체 단위 편집:**
  - 기존 텍스트 한 줄의 내용 교체
  - 이미지·도형의 이동, 크기 변경, 삭제
  - 새 텍스트·이미지·도형 추가
  - 원본 폰트에 없는 글자를 쓰면 앱에 포함된 폰트로 대체
  - **구현 결과 (2026-10-20, M4):** 편집은 객체 편집 기록(쪽마다)으로 쌓고 쪽을 불러올 때마다 다시 적용(replay)하며, 파일을 만드는 길(저장·복구·인쇄·요약·쪽 추출)은 모두 한 곳(`OutputCopyBuilder`)에서 사본에만 확정합니다. 텍스트 편집은 줄(텍스트 객체) 하나 단위로, 원래 글꼴로 바꿔 되읽기·글자 칸 잉크 검사(V14)를 통과할 때만 쓰고 아니면 그 줄 전체를 앱 글꼴(Noto Sans KR)로 씁니다. 묶음(폼 XObject) 안의 객체는 편집할 수 없어(V15) **묶음 전체만** 옮기기·크기·지우기를 합니다(2026-10-20 사용자 결정 U1). 새 텍스트는 암호 문서에서 쓸 수 없고(패치 단계 필요) 이미지·도형은 쓸 수 있습니다. 한 번에 한 객체만 고릅니다(여러 개 선택은 후속). 새 앱 글꼴 텍스트는 쪽 맨 위에 놓이고 저장 전에는 화면에서 글리프 경로라 검색되지 않습니다. 근거·수치: `docs/validation/2026-10-m4-results.md`.
- **M5 — Acrobat 방식 문단 편집:**
  1. 흩어진 텍스트 줄 객체를 좌표·줄 간격·글꼴을 보고 문단 상자로 묶습니다(추정).
  2. 편집하면 그 상자의 **폭은 그대로 두고** 줄바꿈을 다시 맞춥니다. 줄이 늘면 아래로 자라며 **다른 글·그림 위로 겹쳐도 확정할 수 있습니다**(겹치면 점선이 주황색으로 알려 줌, 2026-10-22 사용자 결정 U4). 단 **쪽 아래 가장자리를 넘는 줄은 만들지 않고 다음 쪽으로도 넘기지 않습니다**(넘치면 확정 불가, "줄 N/최대 M" 빨간 표시).
  3. 원본 폰트를 쓸 수 없으면 비슷한 폰트로 대체해 편집합니다.
  4. 저장할 때 다시 개별 텍스트 객체로 풀어서 기록합니다.
  - 표나 도면 표제란에서는 추정이 틀릴 수 있습니다. 사용자가 상자를 나누거나 합치는 기능이 필요한지는 M5 설계 때 결정합니다.
  - **구현 결과 (2026-10-27, M5, 결정 C1~C18 요약):**
    - **C1 편집 진입** — 새 도구 없이 기존 "텍스트 편집"의 확장입니다. 줄을 누르면 문단을 추정해 확신이 높으면 점선 문단 상자와 여러 줄 편집 창을, 아니면 M4의 한 줄 편집을 엽니다. 편집 탭의 "한 줄만" 토글로 언제든 한 줄 편집만 쓸 수 있고, 암호 문서는 문단 편집을 끄고 한 줄 편집으로 되돌립니다.
    - **C2~C4 추정** — 클릭할 때 그 줄 주변의 글 객체만(후보 상한 240개, 글이 1,000개 넘는 쪽은 120개) PDFium 전용 스레드에서 읽고 순수 코드로 계산합니다. 같은 기준선·각도(0/90/180/270°)의 글 객체를 줄로 잇고, 같은 글꼴·크기·색·줄 간격·정렬이면 위아래로 묶습니다. 신뢰도 문턱은 **0.62**(V17), 표 징후(같은 기준선의 여러 칸)·글머리표/목록·짧은 줄 목록은 감점하거나 문단에서 뺍니다. 문턱 아래는 한 줄 편집으로 되돌리고 이유를 알립니다(표 안의 글·글꼴 섞임·확신 낮음).
    - **C5·C16 다시 맞추기** — 편집 창 글과 원문을 비교해 **바뀐 줄부터** 줄바꿈을 다시 하고, 새 줄 끝이 원래 줄 끝과 같아지는 곳부터는 원본 줄을 그대로 둡니다(대체 글꼴로 내려가도 원래 줄 끝을 따라 끊어 줄 수가 늘지 않게 함, C5b). 한글 줄 이음은 문서·열 단위 통계로 어절/글자 단위를 판정합니다(V19: 실제 문서가 글자 단위 줄바꿈이었음). 금칙은 약식입니다.
    - **C6 공간** — 폭은 고정, 아래로 자유롭게 늘어나며 다른 상자 위로 겹쳐도 확정되고(주황), 쪽 아래 경계·다음 쪽은 넘지 않습니다(위 2번). **C13** 상자 좌우 손잡이·속성 패널 "상자 폭"으로 폭을 바꾸면 줄바꿈이 다시 맞춰지고, 틀리게 묶였을 때는 위·아래 줄 포함/제외 단추로 고칩니다.
    - **C7·C12 저장** — 문단 편집이 있는 쪽은 내용 스트림 직접 쓰기(M4x)를 먼저 시도하고(파일을 바꾸지 않는 시험 적용 → 실제 쓰기), 객체 번호 대응이 거절된 쪽만 PDFium 경로로 내려가며, 둘 다 안 되면 이유와 함께 저장을 거절합니다. 지운 원본 글은 가능하면 연산자째 삭제하고(실제 PDF 글 객체 100 %가 가능), 불가능할 때만 `3 Tr` 숨김으로 남기며 저장 뒤 한 번 알립니다.
    - **C8·C10·C11 글꼴** — 원래 글꼴은 문단에 실제 쓰인 (글자 → 글 코드·폭) 표(`FontCodebook`)로 직접 인코딩합니다(ToUnicode가 없으면 PDFium 글과 짝지어 배움, V18: 실제 도면 46.9 % → 100 %). 다시 쓰는 줄 전체를 원래 글꼴로 시도해 한 글자라도 안 되면 그 줄 전체를 대체 글꼴로 배치합니다(고딕 Noto Sans KR, 원본이 명조/세리프면 명조 Noto Serif KR — OFL 번들, 굵게는 렌더 모드 2 + 3 % 선, 기울임은 기울임 행렬로 흉내). 원본 줄과 대체 글꼴 줄이 한 문단에 섞일 수 있습니다(U3).
    - **C9·C14·C15 모델** — 화면 replay와 저장이 같은 줄 배치 데이터를 쓰고, 문단 편집은 하나의 `ReplaceParagraphEdit`(다시 편집하면 대체, 실행 취소 한 번)입니다. 정렬 4종 중 양쪽 맞춤은 마지막 줄을 뺀 줄마다 `TJ` 숫자로 공백 틈을 늘립니다(Tw는 쓰지 않음). **C17·C18** 편집 창은 여러 줄 `TextBox`(Ctrl+Enter 확정, Esc 취소, Enter 줄바꿈, IME 조합 중 키는 입력기에 맡김), 지원 각도는 0/90/180/270°뿐입니다.
    - **알려진 한계:** (1) 추정은 보수적이라 표 칸·범례·2줄짜리 주기·좁은 다단은 한 줄 편집으로 남고(실제 PDF 16쪽 표본에서 3줄 이상 문단은 5쪽, 31 %), "전부 대문자 캡션 목록"형 오탐은 줄 제외 단추로 고칩니다. (2) 새 줄은 쪽 맨 위에 그려지고 태그(접근성) 구조에는 속하지 않습니다. (3) 양쪽 맞춤 문단이 PDFium 바닥 경로로 내려가면 왼쪽 맞춤처럼 저장됩니다. (4) 암호 문서·폼(묶음) 안 글·세로쓰기·임의 각도·OCR 글 층은 대상 밖입니다. (5) 서브셋에 없는 글자를 넣으면 다시 쓰는 줄이 대체 글꼴이 되어 모양이 섞입니다. (6) 편집 창 입력칸의 줄바꿈은 테마 글꼴(PDF 글꼴 아님)이라 실제 결과와 다를 수 있습니다(결과 줄 수는 "줄 N/최대 M"가 맞음). 안내 글씨 크기(11 pt)도 그대로입니다. (7) 큰 도면(205,000 객체) 한 쪽의 출력 사본은 문단 편집 때 약 4 s입니다(성능 절). (8) 실제 한글 IME·마우스·다른 뷰어(Acrobat·PDF-XChange·Foxit·Chrome)·125/150 % 배율은 미확인(검증 필요). 근거·수치: `docs/validation/2026-10-m5-results.md`.
- **대상 PDF (2026-10-15 사용자 결정):** 일반 문서(워드·엑셀 등에서 만든 PDF)와 CAD 도면을 **비슷한 비중**으로 다룹니다. M4·M5 검증 샘플에 둘 다 넣습니다. 글자가 외곽선으로 바뀌었거나 스캔 이미지라서 편집할 텍스트가 없으면 "편집 가능한 텍스트가 없습니다"라고 알립니다.
- **원본 폰트에 글자가 있는지 판정할 수 없을 때 (2026-10-15 사용자 결정):** **원래 글꼴 유지를 먼저 시도**합니다. 원래 글꼴로 바꾼 뒤 결과가 맞는지 확인하고(예: PDFium에 글자를 설정한 뒤 다시 추출해 비교, ToUnicode 역매핑), 맞지 않으면 고친 줄 전체를 앱 폰트로 대체합니다. 확인 방법은 M4 설계 때 검증합니다 (검증 필요). 기술 검증에서 한글 도면은 cmap 조회로 거의 판정되지 않았습니다 (결과 문서 6절).

### 4.2 핵심 설계 결정
1. **편집 중에는 자체 모델이 기준입니다.** 파일을 열 때 PDF의 주석을 `Document` 모델로 읽어 오고, 저장할 때 PDF에 다시 씁니다.
2. **화면을 두 층으로 나눠 그립니다.**
   - PDF 본문은 PDFium이 화면 조각(타일) 단위로 그립니다. **손대지 않은 원본 주석은 PDFium이 원래 AP 그대로 타일에 그립니다**(Acrobat의 곱하기 형광펜 등이 우리 앱에서도 같은 모양). 새로 만들었거나 손댄(이동·수정·삭제) 주석만 타일에서 숨깁니다(M2 결정 D3, 아래 4번).
   - 숨긴 주석과 새 주석은 그 위에 Avalonia가 별도 층으로 그립니다.
   - 그래서 주석을 끌어 옮겨도 페이지 전체를 다시 그리지 않습니다. (알려진 한계: 손대지 않은 원본을 처음 끌거나 지우개로 지우는 동안과 처음 손댄 직후 한 번의 다시 그리기 동안 이중으로 보일 수 있음, 결과 문서 M2 한계 7)
3. **화면용 그리기와 저장용 그리기가 같은 코드를 씁니다.** 주석 모양을 계산하는 코드는 하나만 두고(`IAnnotationPainter` 같은 추상화), 출력만 두 갈래로 나눕니다. 하나는 화면(Avalonia `DrawingContext`)에 그리고, 다른 하나는 PDF AP로 씁니다. 이렇게 해야 화면과 저장 결과가 어긋나지 않습니다. PDFium의 AP 자동 생성은 쓰지 않습니다.
4. **지원하지 않는 주석도 화면에 보여야 합니다.** 본문을 주석 없이 그리면, 읽기 전용으로 보존하는 주석(Link, Widget, Squiggly 등)까지 사라집니다. 렌더링하는 동안에만 Hidden 플래그를 붙이고 `FPDF_ANNOT`로 그린 뒤 원래 플래그로 되돌립니다. 검증 S4에서 확정했습니다 (숨긴 주석은 사라지고 나머지는 그려지며, 저장 파일에 플래그가 남지 않음). **M2에서 다듬은 점(결정 D3):** Hidden은 지원 유형 전체가 아니라 **손댄(소유한) 주석의 PDFium 번호 단위**로만 붙입니다. 모든 지원 유형을 숨기고 Painter로 다시 그리면 다른 프로그램이 만든 원본의 모양이 우리 앱에서만 달라지기 때문입니다. 읽기 전용 주석(Link, Widget, Squiggly, 답글 등)은 그대로 PDFium이 그립니다.
5. **원본 주석 딕셔너리를 보존합니다.** 지원하는 유형이라도 모델이 모르는 키(다른 뷰어 전용 키 등)가 있을 수 있습니다. 저장할 때는 원본 딕셔너리를 그대로 두고, 모델에서 바뀐 키와 AP만 덮어씁니다.
6. **PDFium 문서와 저장 파일은 다를 수 있습니다 (M3a, 2026-10-17).** 패치 단계가 있는 문서에서는 지운 원본 주석이 **세션 동안 살아 있는 PDFium 문서에 그대로 남고**(타일에서만 숨김, 실행 취소하면 원래 키·Popup·답글이 그대로 돌아옴) 저장 때 패치 단계가 파일에서 지웁니다. 새 Line·FreeText 같은 패치 유형은 저장 전에는 PDFium 문서에 아예 없습니다. 따라서 **살아 있는 PDFium 문서를 직접 읽어 파일을 만드는 코드는 반드시 패치 단계를 거쳐야 합니다**(저장·자동 복구·인쇄가 그렇게 합니다. 쪽 추출·분할·내보내기를 만들 때도 같음). 암호 때문에 패치할 수 없는 문서는 M2 방식(PDFium에서 바로 삭제)을 유지하고 새 유형 도구를 끕니다. **M4 확장 (2026-10-20):** 같은 이유로 편집 중인 PDFium 문서에서는 `FPDFPage_GenerateContent`를 부르지 않고 원본 내용 스트림을 바꾸지 않습니다. 파일을 만드는 모든 길은 `OutputCopyBuilder`(주석 Flush → 사본 저장 → 사본에 편집 기록 적용 + 내용 생성 → 패치 단계)를 거치며, 살아 있는 문서를 직접 읽어 파일을 만들거나 그리지 않습니다(인쇄·요약·쪽 추출 포함). **M4x 확장 (2026-10-21):** PDFium의 `GenerateContent`는 셰이딩·패턴·이미지 마스크 색을 다시 쓰지 못해 충실도 보호가 막는 쪽이 있으므로, 그런 쪽(패치 가능한 문서만)은 패치 단계가 쪽 내용 스트림을 직접 고쳐 씁니다(`PdfEditor.ContentStream` 모듈: 바이트 범위를 보존하는 해석기 → PDFium 객체 목록과 대응 검증 → 끄기·옮기기는 그 객체의 연산자만 고치고 나머지는 원본 바이트 그대로, 새 객체는 원본을 `q … Q`로 감싼 뒤 기본 상태에서 덧붙임). 대응 검증·재작성 검사·저장 뒤 모양 비교 중 하나라도 어긋나면 저장을 멈춥니다. 해석기는 PDFium을 부르지 않으므로 일반 스레드에서 돕니다. **M5 확장 (2026-10-27, 문단 편집의 저장 경로):** 문단 편집이 있는 쪽은 ① 파일을 바꾸지 않는 시험 적용(`IContentRewriteProbe.CheckContentRewrites`: 객체 번호 대응·글꼴 자원·상태 해석까지, 결과를 이어지는 실제 쓰기가 같은 쪽 내용·같은 편집일 때만 재사용)으로 직접 쓰기가 되는지 보고 ② 되면 지울 원본 글을 연산자째 삭제(뒤 글의 위치가 이 글의 이동량에 기대면 `3 Tr` 숨김)하고 새 줄을 원본 글 객체에서 읽은 글꼴 자원 이름·크기·색 상태에 위치만 바꿔 `TextLineWriter`로 덧붙이며(코드북으로 인코딩한 글 코드를 그대로 씀, 새 글꼴 객체 없음) ③ 거절된 쪽만 PDFium 경로로 내려가고 둘 다 안 되면 이유와 함께 저장을 멈춥니다. 앱 글꼴 줄은 쪽마다 가족(고딕/명조)별로 서브셋 하나를 나눠 씁니다. 직접 쓴 쪽도 "화면 모양 ≡ 저장 파일을 다시 연 모양" 비교를 하되, 화면의 PDFium 글 객체가 못 그리는 자간·양쪽 맞춤 늘임 줄 주변 띠만 비교에서 뺍니다.

## 8. 데이터 흐름·저장·오류·테스트 (승인됨, 2026-10-15)

### 8.1 주석 데이터 흐름
- **열기:** PDFium으로 주석을 읽어 `Document` 모델로 변환합니다. 모델의 각 주석은 원본 PDF 주석을 가리키는 참조(페이지 번호 + 주석 인덱스 또는 `/NM`)를 함께 가집니다.
- **편집:** 모든 변경은 명령(Command) 객체로 실행해서 실행 취소 스택에 쌓습니다. 주석과 페이지 조작(M1)이 같은 스택을 씁니다.
- **PDFium 문서에 반영하는 시점 (Flush, M2 결정 D4):** 명령은 모델만 바꾸고 PDFium 문서는 건드리지 않습니다. 모델의 변경은 **저장·인쇄·자동 복구 직전에만** PDFium 문서에 반영(Flush)합니다. Flush는 트랜잭션이 아니므로 도중에 PDFium 오류가 나면 저장·인쇄·복구를 중단하고 오류를 알립니다(그 세션은 다시 열어야 할 수 있음).
- **저장:** 모델과 원본의 차이를 계산해 PDF에 반영합니다. (M2는 이 단계를 PDFium만으로 하고 PDFsharp 후처리는 쓰지 않음 — 불투명도는 `FPDFAnnot_SetAP`가 `/GS` ExtGState를 붙여 줌, V9. M3a부터는 PDFium에서 만들 수 없는 유형·Popup·글꼴·이미지·첨부를 아래 패치 단계가 임시 파일에 씁니다: 지울 번호를 뒤에서부터 지우고, 만들 주석을 끝에 붙이고, 손댄 원본에는 바뀐 키만 쓰고, 개수를 대조함.)
  1. 삭제된 주석을 제거합니다.
  2. 새 주석을 만듭니다.
  3. 수정된 주석은 바뀐 키만 덮어씁니다(4.2-5).
  4. 생성·수정된 주석의 AP를 Painter로 새로 씁니다.
  5. 8.2의 저장 절차로 파일에 기록합니다.
- **지원하지 않는 유형:** 원본 PDF의 주석 중 모델이 지원하지 않는 유형은 읽기 전용으로 보존합니다. 화면에는 표시하고(4.2-4), 저장할 때는 손대지 않습니다.

### 8.2 저장과 오류 처리
| 항목 | 동작 |
|---|---|
| 기본 저장 방식 | 전체 저장(`FPDF_SaveAsCopy`, 증분 플래그 없음). 증분 저장은 v1에서 쓰지 않습니다. |
| 원본 보호 | ① 같은 폴더의 임시 파일(`~<이름>.tmp`)에 씁니다. ② PDFsharp 후처리를 이 임시 파일에 적용합니다 (S1에서 2단계 저장으로 확정: 한글 FreeText 등 폰트 자원이 필요한 AP는 PDFium만으로 만들 수 없음). 후처리할 것이 없으면 건너뜁니다. **M4(2026-10-20):** 편집 기록이 있으면 PDFsharp 패치 앞에 *내용 단계*가 들어갑니다 — 임시 파일을 PDFium으로 열어 편집한 쪽에 기록을 적용하고 `GenerateContent`로 쪽 내용을 다시 쓴 뒤 다시 저장합니다(편집 기록이 없으면 건너뜀, 암호 문서도 됨). 앱 글꼴 텍스트는 패치 단계가 쪽 내용 끝에 진짜 글자로 붙입니다. **M4x(2026-10-21):** 내용 단계의 충실도 보호가 끝내 막는 쪽은 PDFium 다시 쓰기를 건너뛰고 패치 단계가 내용 스트림을 직접 고쳐 씁니다(4.2-6). **M3a에서 구현함(2026-10-17):** 패치 계획(`PatchPlan`)을 임시 파일에 한 번에 적용하고 저장한 뒤 ③에서 주석 수를 `PatchPlan.CountDelta`까지 반영해 대조합니다. 같은 패치 단계를 자동 복구(복구용 PDF 사본)와 인쇄(임시 사본)도 거칩니다. 암호 PDF는 소유자 암호가 있을 때만 패치할 수 있어(V6), 패치할 수 없는 문서는 새 유형 도구를 끄고 패치가 필요한 원본을 읽기 전용으로 둡니다. ③ 임시 파일을 PDFium으로 다시 열어 페이지 수와 주석 수를 확인합니다. ④ `File.Replace`로 원본과 교체합니다. 어느 단계든 실패하면 임시 파일을 지우고 원본을 그대로 둔 채 오류를 알립니다. |
| 자동 복구 | N분(기본 5분, 설정에서 변경)마다 `%LOCALAPPDATA%\<앱 이름>\Recovery`에 편집 상태를 기록합니다. 기록하는 것은 원본 경로, 원본 해시, 그리고 **Flush를 마친 PDF 사본**입니다(M2 결정 D5: 모델 JSON 스냅숏을 따로 두지 않고, 주석이 반영된 PDF 한 가지만 기준으로 삼아 서로 어긋나지 않게 함). 원본 파일은 건드리지 않습니다. 정상 종료하거나 저장하면 해당 복구 파일을 지웁니다. 다음 실행 때 복구 파일이 남아 있으면 복구할지 묻습니다. 원본 해시가 바뀌었으면 그 사실을 함께 알립니다. |
| 암호가 걸린 PDF | 열기 암호를 물어 엽니다. 편집은 허용합니다. 저장할 때 암호화가 유지되는지는 검증 V6으로 확인합니다. 유지되지 않으면 "암호화가 해제된다"고 경고하고, 원본 덮어쓰기는 막고 다른 이름으로 저장만 허용합니다. 권한 암호(인쇄·수정 제한)는 표시만 하고, 제한은 PDFium의 권한 플래그를 따릅니다 *(검증 필요)*. |
| 손상된 PDF | PDFium이 자동 복구해서 열면 "파일이 손상되어 복구한 상태로 열었다"고 알리고, 다른 이름으로 저장하기를 권합니다(감지 방법은 검증 V8). 열 수 없으면 `FPDF_GetLastError` 코드를 사용자 메시지로 바꿔 보여 줍니다. |
| PDFium 호출 오류 | `Pdf.Native`가 오류 코드를 예외로 바꿉니다. UI는 작업 단위로 예외를 잡고, 문서 상태는 명령 실행 전 상태로 되돌립니다. |
